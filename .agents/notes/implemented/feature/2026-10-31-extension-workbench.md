# Agent Note: 扩展页采用分栏工作台并按内容宽度切换目录与详情

Status: implemented

## Problem

MCP、技能、命令、规则的页头和列表密度不一致，服务器行同时承载状态、配置标签与操作，命令和规则的固定宽目录会挤压窄窗编辑区。用户已选定分栏工作台及四页内容布局，并明确要求保留现有功能。

## Decision

四页共用简洁页头及扩展导航。宽窗扩展导航纵向显示，模块收窄后改为顶部横排。MCP 使用服务器目录和详情，工具权限为主体，连接配置只读摘要，编辑仍使用原配置弹窗。技能使用全宽列表或网格；命令与规则保留目录和编辑器，窄内容区在目录与详情之间切换，不因窗口大小重挂编辑器。

布局只读取现有主题 token，保留字号和明暗偏好。MCP 新增仍写应用设置，修改仍写原来源；运行状态、权限、认证、JSON 导入、环境变量、工作目录和请求头不改变。技能三种导入、资源重载、目录、视图偏好和永久删除确认保留。命令的保留名校验、提示词高亮和参数识别不变；规则的即时开关、显式保存、全局/项目范围及五模式边界不变。

## Alternatives considered

- 原有横向页签和整行 MCP 卡片改动最小，也方便扫描少量服务器；但服务器权限和动作仍挤在同一行，不能充分解决内容层次问题。
- 全部改成卡片网格能提供更松的浏览密度，适合技能；但命令、规则和权限需要连续编辑，整齐目录加主体更适合日常操作。技能仍保留原有网格切换。
- 窄窗继续压缩并排目录可以减少一次返回；但正文宽度会不足，因此用 CSS 切换目录与详情并保留同一编辑实例。

## Consequences

四页共享内容层次与操作密度，宽窄及深浅色没有横向溢出、遮挡或草稿丢失。目录默认选择以工作区、来源、名称保存，启停重排后仍显示同一台服务器；删除或改名后回退到有效条目。配置摘要只渲染字符串字段，手写非法配置不会成为 React 对象子节点。工具空态也以实时状态优先，旧探测错误不会覆盖已连接、连接中和待登录状态。

窄窗切换只隐藏目录或详情，不卸载命令/规则编辑器；短窗允许整组原生滚动以访问末项和保存区。扩展内的命令胶囊采用中性主题样式，会话内的命令胶囊保持原样。所有现有入口、配置字段、写入目标与校验保留。

测试替换主进程桥，不代表真实远端 MCP、系统文件窗口或安装包验收；文件选择桥需要匹配的新 preload 才能使用。
