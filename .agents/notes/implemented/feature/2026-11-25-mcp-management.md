# Agent Note: MCP 工作台区分连接状态、离线工具目录与权限

Status: implemented

## Problem

缓存里有工具名不代表服务在线。只有名字，用户也无法按用途查找工具、判断参数开销，或区分进程退出、端口拒绝和握手超时。

## Decision

- 目录和详情使用当前工作区的连接状态；失败优先于缓存。工作台打开期间每两秒读取一次管理器，只取选中项的诊断和工具定义。已取得同次连接的定义不再重复传输。读取不启动 agent-host，也不创建 MCP 连接。
- SDK 按游标读齐工具，实时目录使用与工具注册相同的命名规则。成功结果缓存描述与 schema；旧缓存仍可按名字管理权限。失败快照不把缓存工具报告为在线工具。
- 单工具调试只发给当前连接。主进程现读权限文件，按参数规则审批，执行工作区授权，审计不保存参数正文。运行端由注册全名反查原始工具名，拒绝未知工具。估算分开计算可用定义和直接暴露的定义：禁用调用不等于取消注册。
- 标准错误以连接尝试为界，最多十行。先拼接分块再脱敏；过长行整行略去。退出码仅在 STDIO 子进程确实提供时记录。SDK 的公开接口不保留退出码，传输适配器只观察现有子进程的 exit 事件，拿不到时不推断。
- 目录筛选保留有效选中项；切服务重建工具搜索、权限过滤与凭据显示状态。工具区独立滚动，批量操作始终作用于该服务器全部工具，并在成功保存后反馈。表单和 JSON 编辑同一份草稿，保留未知字段、含空格的参数边界和启停状态。来源切换先检查各层同名项，目标写成功再移除源项。项目文件沿用 Pi 的 `.pi/mcp.json`。
- 运行、配置和权限的既有决定见[配置分层与认证](../architecture/2026-10-04-mcp-config-layers-and-oauth.md)、[重载状态回传](../bug-fix/2026-10-22-mcp-reload-reports-state.md)。本篇部分取代[原 MCP 详情设计](./2026-11-01-mcp-detail-cleanup.md)，[有界分栏](../bug-fix/2026-10-31-mcp-workbench-bounds.md)保持有效。

筛选只更改视图，计数以当前搜索匹配的工具为准；批量入口独立，超过十项且权限不同时须确认覆盖全服务。配置和权限分标签，在同一服务内保留筛选。顶栏分别汇总已启用服务的可用目录与在线直接暴露的定义；不把 Code Mode 按需发现的完整 schema 算作常驻开销。慢连接从实际尝试时间计时，终止操作携带尝试身份，仅取消这次连接，不改配置或自动重试。

## Alternatives considered

固定底部配置能省一次点击，但窄矮窗口要同时容纳工具过滤和多组环境变量，挤压工具阅读区；改为同级标签。批量修改后撤销方便连续尝试，但权限可能在撤销前已放行调用，所以对大型混合权限目录采用写入前确认。

另起临时进程调试可以验证孤立配置，却绕开当前连接、认证和调用策略，不能代表工作区实际可调用。把工具定义和 stderr 放进每个会话的状态广播能省一条读取接口，却会在日志刷新时重复复制整份目录并触发工具投射；改为工作台定向读取。

## Consequences

断连、缓存和未启用有不同的显示与可用操作。没有活动连接时仍可看缓存定义，但不可发送 Test Call。标准错误不完整或服务从未输出时，界面显示缺项，不编造退出码。完整配置和单项复制会按用户操作写入系统剪贴板。

## Verification

收尾版 [Electron 验收记录](../../../evidence/2026-11-25-mcp-management/REPORT.md)：8 / 51 / 81 工具和远程慢连接场景，125 项通过。真实 HTTP 握手在取消后断开；旧请求不能终止重试。生产构建包含渲染层和主进程类型检查。

真实 STDIO 定向测试 `mcp/inspection.integration.test.ts` 通过：读齐两页共 80 个工具、按原名调用、阻止错名；失败进程以 7 退出，12 行 stderr 只保留末 10 行且不含测试密钥。Electron 场景 `npm run ui:check -- mcp-management` 通过，覆盖 80 项滚动、名称/描述/权限筛选、切换清空、凭据显示后重新遮罩、调试、深浅主题和窄窗。主进程另以临时目录验证权限审批、审计和来源冲突。
