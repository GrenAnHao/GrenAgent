# Agent Note: 扩展目录区分资源管理与实际注入

Status: implemented

## Problem

技能开关旁的垃圾桶会删除整个本地目录。新用户要从空白表单猜命令语法；规则管理页既看不见仓库指令，也无法判断打开的文件和下一轮上下文是什么关系。

## Decision

- 四页共用同一顶栏。技能保留列表和网格；点击行打开只读源码预览，再显式编辑。文件树按目录展开时读取，不遍历链接。保存只替换打开时预览的普通文件，磁盘已变就保留草稿并报错。
- 技能开关继续沿用运行时按名称匹配的偏好。归档将整个目录移到同一作用域的 `skills-archive/archive-*/<原目录名>`，禁用该名称并给出恢复路径。删除放在“更多”菜单末项，确认框展示即将移除的完整目录。
- 命令模板在编辑器中生成草稿，保存后才注册。`$ARGUMENTS` 走 Pi 原生参数展开；文件路径走 `@{文件}` 命名参数；Git Diff 插入读取差异的提示，不在编辑器里执行 shell。
- 仓库指令按当前及已关联项目的根目录列出。按 Pi 的同目录优先顺序标记生效文件；保留被覆盖的候选以便查看和修改，不复制成自定义规则。普通文件可原地保存，链接只读。自定义规则保留作用域和模式，可选 `globs` 匹配本轮显式引用的项目相对文件路径。未配置匹配式的旧规则不变。
- 规则目录以项目名区分同名仓库指令，保留目录末段供核对；搜索结果按范围计文件数。两类规则都先预览，再显式编辑，保存使用所选文件身份而不是列表位置。顶栏只汇总磁盘上已启用的自定义全局规则正文；仓库按根目录去重，单文件体积则随当前编辑正文变化。

## Alternatives considered

把仓库指令导入规则可以复用启停控件，但 Pi 本来就会读取原文件，复制将重复注入，也无法表达同目录被覆盖的 CLAUDE.md。只停用技能不移动文件最省 I/O，却无法区分临时关闭和从目录归档。

只用完整路径作副标题不必改动文件名，但窄栏里相同的盘符和公共目录挤掉了项目名。目录行因此优先展示能区分仓库的最短名称，文件名另作标签；完整路径留给悬停和复制。

## Consequences

描述中要求显式调用会改变技能徽章，只有 SDK 的 `disable-model-invocation: true` 才将启用技能描述排除在预算之外。规则的字符数与 token 估算仅针对正文；有模式或文件条件的全局规则仍须匹配才会注入，项目文件不占全局估算。归档保留脚本和资源，恢复时可将目录移回原位置并启用。

沿用[扩展页草稿保护](./2026-11-01-extension-pages-cleanup.md)与[实际规则注入提示](./2026-11-18-context-rule-injection-notice.md)；后者报告当轮实际生效的自定义规则，面板预算不替代它。
