# Agent Note: Pi SDK 1.6.1 补丁升级

Status: implemented

## Problem

上游 Pi SDK 发布 1.6.1（含 Windows 下 `git var GIT_SHELL_PATH` 查找、Gemini 4 `xhigh` thinking 级别映射修复、`after_provider_response` 在 4xx/5xx 与重试时触发、`showCacheMissNotices` 拆分为四项独立通知设置等），`pi-ai` 同步将 `@google/genai` 升至 `3.6.1` 并直接引入 `@aws-sdk/credential-provider-node@3.972.82`。同时上游 `dist/utils/shell.js` 新增第 3 步 `findGitBashOfGitOnPath()`，将原有第 3 步通用 `bash.exe` 回退注释顺延为 `// 4. Fallback:`，导致现有 `cli/scripts/patch-pi-shell.mjs` 的锚点失效。

历史决定审计：延续 [三个运行入口的依赖升级](2026-11-24-runtime-dependency-refresh.md)、[Pi SDK 1.5.2 补丁升级](2026-11-18-pi-sdk-1.5.2-upgrade.md) 与 [1.4.0 升级](2026-11-01-pi-sdk-1.4.0-upgrade.md) 的三入口精确锁定、双锁同步与 `postinstall` 补丁边界；保留各自 `pnpm-workspace.yaml` 的 `allowBuilds`、`@colbymchenry/codegraph` 固定版本（`1.6.4`）与历史例外条目。经检索仓库代码，已移除的 `showCacheMissNotices` / `SettingsManager.getShowCacheMissNotices()` / `setShowCacheMissNotices()` 与 `after_provider_response` 均无活跃调用，`SessionUiAdapter` 兼容新增可选字段 `blockedKind`。

## Decision

- CLI、extensions、Electron 三入口直接 Pi 依赖统一精确锁定 `1.6.1`，同步刷新三份 `pnpm-lock.yaml` 与三份 `package-lock.json`（不改写未参与安装的历史 `extensions/bun.lock`）。三个入口的 `pnpm-workspace.yaml` 仅对刚发布的八个 `@earendil-works/pi-*@1.6.1` 包追加精确 `minimumReleaseAgeExclude`，不放开命名空间或全局最短发布期检查。
- 将 `cli/scripts/patch-pi-shell.mjs` 的 `fallbackAnchor` 更新为 `// 4. Fallback: search bash.exe on PATH (Cygwin, MSYS2, WSL, etc.)`，使上游 `1.6.1` 新增的 `findGitBashOfGitOnPath()` 自动走补丁后的 `spawnWhere`（受信任绝对路径 `System32\where.exe` + 注册表 PATH）覆盖 Git 2.47+ 与 shim 安装，同时保留 `findGitBashFromGitCmd()` 紧跟在其后以兼容 Git < 2.47；`cli/scripts/patch-pi-edit-preview.mjs` 锚点未变继续沿用。在 `cli/src/pi-install-patches.test.ts` 补充 `git var GIT_SHELL_PATH` 与 shim `git.exe` 用例。
- 同步重新生成 `docs/third-party-dependencies.md`（944 个包，包含 `@earendil-works/pi-*@1.6.1`、`@google/genai@3.6.1` 与 `@aws-sdk/credential-provider-node@3.972.82`），并通过 `--check` 校验。
- 沿用 [Pi SDK 1.5.2 补丁升级](2026-11-18-pi-sdk-1.5.2-upgrade.md) 的 Windows 临时库释放约定，在 `extensions/multi-agent/ultra-sdk.integration.test.ts` 与 `electron-agent/electron/app/sessionPreferences.integration.test.ts` 的 `afterEach` 中先关闭 `sharedLedger` 与 `sharedOriginRegistry`，再删除临时 `agentDir`，避免 `node:sqlite` 文件锁导致 `EBUSY` 清理失败。

## Alternatives considered

- 删除 `findGitBashFromGitCmd()` 仅保留 `spawnWhere` 补丁：最强理由是进一步缩小私有补丁面、完全复用上游 `1.6.1` 的 `findGitBashOfGitOnPath()`；不用是因为 `git var GIT_SHELL_PATH` 要求 Git 2.47+，旧版或便携版 Git for Windows 在该命令失败后仍会退回 WSL `System32\bash.exe`。
- 等待八个 `1.6.1` 包满 24 小时后再升级以避免新增 `minimumReleaseAgeExclude`：最强理由是不必维护临时版本例外；不用是因为用户明确要求立即升级至 `1.6.1`，且精确版本枚举不放宽供应链策略。

## Consequences

- 收益：三入口继续共享单一 `1.6.1` SDK 与传递依赖图，获得上游 `1.6.1` 修复（包括 Windows Git Bash 查找、Gemini 4 `xhigh` 映射与大长行/长历史性能修复）；两个 Windows 集成测试临时目录清理不再偶发/必发 `EBUSY`。
- 代价：后续升级仍需同步维护三份清单、六份锁文件、`minimumReleaseAgeExclude` 与 `shell.js` / `edit-diff.js` 补丁校验；`npm ci --dry-run` 在 `electron-agent` 仍依赖同目录 `.npmrc` 的 `legacy-peer-deps=true`。
- 边界：本次只使用隔离临时目录与本地回环桩验证，真实远程供应商请求、OAuth 登录、CodeGraph 重建索引及最终安装包打包未实测；未修改渲染 UI，未运行 `ui-harness`。
