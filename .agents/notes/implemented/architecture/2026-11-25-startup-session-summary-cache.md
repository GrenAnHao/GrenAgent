# Agent Note: 首屏恢复一个会话，侧栏在后台核对磁盘摘要

Status: implemented

## Problem

工作台为恢复记住的一份会话而等待所有项目的历史。2026-11-25 本机 1,458 个 JSONL 共 1.66 GiB，启动时全量列表最慢 5.69 秒。10 月测得 265 份历史时只需约 0.29 秒，曾据此选择不持久化摘要。开发模式偶尔还会重建 Vite 依赖；它影响冷启动，但不是会话列表的开销。

## Decision

- 恢复记住的会话时，主进程只检查托管目录中对应的 JSONL：等待迁移恢复，检查归档、可见性和当前 cwd，不读侧栏索引。会话换过项目就回到当前项目。项目草稿沿用原身份，临时对话只核对自己的 works 子目录及对应的会话目录。已使用或无法安全复用的临时目录不作为空白对话。
- 对已删除、已归档等不再有效的启动目标，自动回退到草稿。暂时读不了时保留原位置，用户可以重试恢复或明确新建对话；只有新建成功后才改记忆。
- 首屏仍等待原会话内容。首个工作区就绪并绘制后，才为侧栏读取全量列表、登记的项目，随后再考虑孤儿清理；已知目标不再额外扫描其项目的所有会话。目录结果沿用会话变更代次，不能覆盖刚发生的移动或删除。
- 每个 Agent 数据目录有独立的 `session-summaries.v1.json`，只存列表元数据和迁移保留根，不复制消息历史。目录枚举决定有哪些会话；按路径、大小、mtime、ctime 和文件身份复用磁盘摘要，移除消失的记录。扫描新增/变更文件沿用字节标记解析，最多同时读四份；并发请求共享源解析。更改解析含义需要升级索引版本。
- 先写临时文件再原子替换索引，不能写索引时仍可列出会话。磁盘摘要只参与展示或保护目录，不能授权打开、修改或删除会话。确认自动删除孤儿时，需要从源记录核对哪些 scratch 仍被引用；这不是列出侧栏的前置工作。

本篇和[启动回到上次会话](../feature/2026-10-19-startup-restores-last-session.md)部分重叠：保留目标选择，改变检查范围与时机。保留[跨项目移动](../feature/2026-11-17-session-project-transfer.md)的恢复闸门与显式失效。仅内存缓存的理由保存在冻结的 docs/decisions/electron-agent/startup/2026-10-04-session-list-scan-cache.md。

## Alternatives considered

只持久化、仍等整个列表，路径改动小，但首次建库、缓存丢失或历史集中更新时仍会挡住恢复。只把扫描推迟、不做磁盘摘要能先看到工作台，但每次启动仍会重复读全库，刚能操作时又会争用磁盘与内存。

## Consequences

首次建索引的 I/O 仍然存在，但在首屏之后；后续进程冷启动的侧栏只需核对文件属性、解析变动的 JSONL。摘要可能显示用户显式设置的标题，包括很长的标题；原始聊天内容和归档状态不从这份缓存恢复。文件在外部被替换、缓存损坏或版本不合时，按源文件重建。

## 验证

`workspaceStartupLookup.test.ts` 的托管路径、隐藏/归档、迁移、草稿判定通过；`sessionSummaryCache.test.ts`、`workspaceService.test.ts`、`workspaceServiceTransfer.test.ts` 的新增、替换、删除、冷命中、损坏重建和保护根等 62 项通过。目标选择和草稿单测 14 项通过，`npm run ui:check -- startup-session` 的 26 个断言通过：挂起目录时操作窗口、过期列表、恢复重试和显式新建均在真实 Electron 窗口中验证。同规模 1.66 GiB 的历史、19 次独立 Electron 进程启动：从 Logo 到原会话可输入的中位数，原版 4.20 秒，首次建索引 3.18 秒，已有索引 3.17 秒。样本、时间口径与历史读取字节见 `.agents/evidence/2026-11-25-startup-latency/REPORT.md`。
