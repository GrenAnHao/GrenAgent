# Agent Note: Pi SDK 升到 1.3.0，before_agent_start 只对用户输入注入上下文

Status: implemented

## Problem

electron-agent / extensions / cli 停在 pi 1.1.0。1.2.0 和 1.3.0 之间有几处会改变本仓库运行行为的上游变更：

- `before_agent_start` 从 1.2.0 起对 `pi.sendMessage(..., { triggerTurn: true })` 开的一轮也会触发，事件变成按 `messageType` 区分的联合类型：`"user"` 带 `prompt` / `images`，`"custom"` 带 `message`、没有 `prompt`。本仓库 goal 续跑、后台任务唤醒、子代理回报、自动压缩后续跑都走 triggerTurn。
- 一轮开始的过程（含 `before_agent_start`）里会话就算忙：`ctx.isIdle()` 为 false，`pi.sendUserMessage()` 必须带 `deliverAs`。
- 1.3.0 把内部依赖钉成精确版本，并去掉了 `@earendil-works/chord` 依赖。
- CodeGraph（`@colbymchenry/codegraph`）已经是 npm 最新的 1.6.2，main 上未发布的提交只有 Fixes，没有 SDK 接口变化，这次不动。

## Decision

- 三处 `package.json` 的 `pi-ai` / `pi-agent-core` / `pi-coding-agent` 写成精确的 `1.3.0`，和 pi 自己钉死内部依赖（pi #10865）保持一致，避免 `^` 解出比 coding-agent 内部更新的 pi-ai 造成两份副本。
- `pnpm-workspace.yaml` 的 `minimumReleaseAgeExclude` 放行 1.3.0（发布不满最短发布期），删掉不再需要的 chord 条目；pnpm 锁和 npm `package-lock.json` 一并刷新。
- `before_agent_start` 的处理按用途分两类：
  - 每轮按用户输入注入隐藏消息的，遇到 `messageType === "custom"` 直接返回，保持 1.1.0 时的行为：`memory`（要 `event.prompt`，否则抛 TypeError）、`fable-behavior`、`code-retrieval`、`diagram-hint`。`loop-guard` 的「新用户消息清计数」同理只对用户输入生效，goal 续跑里的重复调用继续累计。
  - 改 `systemPromptOptions`、对齐工具集或投递待办提醒的，对两种轮次都生效：`context-rules`、`working-directory`、`agent-mode`、`mcp`、`rulebook`、`session-memory`。前两者如果跳过 custom 轮，那一轮的系统提示会和前后不同，打掉前缀缓存。
  - 判断写 `=== "custom"`，不写 `!== "user"`：老测试和老调用方传的事件没有 `messageType`，按用户输入处理。
- `im-gateway` 一律带 `deliverAs: "followUp"` 调 `pi.sendUserMessage`。SDK 的 `sendUserMessage` 是异步报错，原来「先不带、抛错再带」的 try/catch 从没生效过；1.2.0 之后启动中的一轮也算忙，不带就会丢消息。
- MCP 扩展给每个 server 的命名空间加 `aliases: [server]`（1.2.0 新字段），codemode 的 `describeNamespace("antd")` / `searchTools({ namespace })` 可以直接写 server 名，和 pi 内置 MCP 一致。

### 后续接入的上游能力

`reachesTools`、codemode 运行时长、`argumentsError` 的展示、read 行号对齐 `formatReadLineRange`、models.json 的 `$schema` 已在 [接入 pi 1.2 / 1.3 的五项新能力](../../implemented/feature/2026-10-17-pi-1.3-capabilities.md) 落地。`sessionShareDestination` 和 OpenRouter 按 key 列模型桌面端仍没有入口。

### 用户侧需要知道的上游变化

- `kimi-coding` 改走 OpenAI Chat Completions（`https://api.kimi.com/coding/v1`），自己在 models.json 覆盖过它 baseUrl 的，必须带 `/v1`。供应商预设里本来就写的是 `openai-completions`，不用改。
- 切换模型时丢弃旧模型的 thinking；恢复会话时还原会话里激活过的工具；提示词模板保留空的引号参数（命令胶囊发出的 `""` 不再错位）。

## Alternatives considered

- **让所有 `before_agent_start` 处理对 custom 轮也注入（接受上游新默认）**：理由最强的一点是 custom 轮里模型也能拿到最新的行为约束和代码索引提示。不选：这些消息会持久化进会话，每次后台任务唤醒、goal 续跑都再塞一份 fable-behavior 全文，token 成本随唤醒次数线性增长，而上一条用户输入时注入的那份仍在上下文里。上游文档也建议「用 messageType 跳过 custom 消息开的轮」。
- **依赖继续写 `^1.3.0`**：和以前的写法一致，小版本自动跟进。不选：pi 1.3.0 修 #10865 时把内部包钉成精确版本，我们写 `^` 会在 pi-ai 先发小版本时装出两份 pi-ai，扩展和宿主拿到不同的 `ModelRuntime` 类型（本仓库 tsc 基线里就有这种跨副本报错）。
- **把 CodeGraph 升到 GitHub main**：main 比 v1.6.2 多 150 多个提交，修了大量 C++/Go/React 链接问题。不选：未发布，打包依赖 npm 上的平台二进制包，等下一个 npm 版本再升。

## Consequences

- 收益：去掉 memory 在 triggerTurn 轮里的崩溃；后台唤醒、goal 续跑不再重复注入隐藏上下文；IM 网关在会话忙时不再丢消息；锁文件少了 chord 及其 esbuild 平台包。
- 代价：custom 轮里模型看不到这一轮新算的 fable-behavior / 代码索引提示，靠的是上一条用户输入时注入的那份；以后新增「每轮注入」的扩展要记得同样判断 `messageType`。
- 精确版本意味着每次升级 pi 都要手动改三处 package.json 和 release-age 放行表。
- 合并时注意：主仓库工作区有未提交的 `electron-agent/package.json` / `package-lock.json` 改动，和本分支的锁文件会冲突，合并后需要在 `electron-agent/` 重跑 `pnpm install` 和 `npm install --package-lock-only`。
