# Agent Note: 工作台明暗只换语义色，不换组件样式

Status: implemented

## Problem

浅色为 MCP 目录另包列表、给选中项换白卡和阴影、把删除按钮改灰。这些例外使换肤同时改变外形，并让用户难以辨认同一项操作。Windows 原生粗滚动槽和会折行的服务器名在窄列进一步挤占正文空间。

## Decision

在根主题同时提供两组同名的语义颜色。组件只认表面、分割线、品牌选中、危险、状态等角色，不根据明暗切换 CSS 或容器。标题、导航、密集控件和工具名用一套桌面字号梯度；用户设定的会话阅读字号另行保留。全局滚动条使用同一份样式，Shadow DOM 复用它；刻意隐藏的重复滚动条不重新显示。

浅色的外轨、二级导航、画布与卡片分别为 #ECEEEB、#F4F5F3、#F8F9F8、#FFFFFF。鼠尾草绿色用于当前位置、活动页签和主操作；红色表示危险操作。不以浮起的纯白卡表示选中。滚动条的两轴均为 6px，轨道透明，只改变滑块的明度。

这取代了[固定工作台主题](../simplification/2026-10-30-single-workbench-theme.md)以前为浅色单独规定的组件配色和[空白页设计](../bug-fix/2026-10-31-responsive-empty-chat.md)中随宽度放大的欢迎标题；原有明暗偏好、输入框响应式布局及内容字号设置保留。

## Alternatives considered

- 给浅色逐页补覆盖能快速改动某一张截图，但很难保证同一窗口切换主题后，边框、滚动宽度和内容位置保持相同。统一以暗色组件为模板，只调整公共组件及两套颜色的映射。
- 把整个应用统一缩放可一次提高密度，但也会缩小图标、命中区域和用户指定的聊天正文字号。改用标题、正文和辅助文字各自的语义角色；服务器名省略不折行。

## Consequences

目录宽度不足时服务名保持单行，可悬停查看全名。切换主题不重新计算字号或边框宽度；普通控件共享 Ant 主题配置。Lobe 普通按钮会在浅色选 outlined、深色选 filled，因此工作台使用 WorkbenchButton 显式固定默认形态；调用方指定的 primary、text 或其他变体照旧。默认 filled 会把未指定颜色的危险按钮解释成中性色，因此共享按钮把 danger 显式映射成危险色，防止命令页的「删除」褪成灰字。短暂淡变只作用于背景和边线，文字和 SVG 的前景不逐层过渡，减少动态效果时不淡变。
