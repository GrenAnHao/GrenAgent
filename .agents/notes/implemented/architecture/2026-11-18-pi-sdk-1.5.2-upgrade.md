# Agent Note: Pi SDK 1.5.2 补丁升级

Status: implemented

## Problem

pi-ai 1.5.1 在 Anthropic OAuth 请求中报告了过旧的客户端版本；[上游 1.5.2](https://github.com/earendil-works/pi/releases/tag/v1.5.2) 已修复。现有 [1.5.1 升级](2026-11-10-pi-sdk-1.5.1-upgrade.md) 与 [1.4.0 升级](2026-11-01-pi-sdk-1.4.0-upgrade.md) 的三入口锁定、两种锁文件及安装补丁策略继续适用，模型编辑和 OAuth 凭据归属决定不变。

## Decision

CLI、extensions、Electron 三入口统一精确锁定 Pi SDK 1.5.2，保留安装补丁、供应链配置和 Electron 的 AWS 版本覆盖。真实会话测试将加载的 SDK 版本与 CLI 清单比较；SDK 兼容性测试先释放测试用量库，再在 Windows 上删除临时目录。

## Alternatives considered

- 只升级 pi-ai 的直接声明，差异最小；但 coding-agent 和 agent-core 精确依赖同版 pi-ai，会保留两套 provider 运行时，因此同步升级。

## Consequences

每个入口只解析同版八个 Pi 包，不引入第二份 provider 运行时；后续发版仍须同步三份清单和两种锁。实际 OAuth 登录、供应商请求和安装包未验。

## 验证

- 三入口 `pnpm install --frozen-lockfile` 通过；安装解析图及 npm / pnpm 锁各含八个 1.5.2 Pi 包。
- CLI 补丁测试 11 例通过；extensions 的 `pnpm exec vitest run _shared/pi-sdk-compat.integration.test.ts` 4 例、Electron 的 `pnpm exec vitest run electron/app/modelCompat.integration.test.ts electron/app/sessionWorkflowSdk.test.ts` 9 例通过；CLI 与 Electron 的 `npm run build` 均通过。
- 同批运行的 `gren-runtime.test.ts` 有 3 个工厂计数断言失败：当前工作区已有的会话迁移改动在普通与系统 worker 都增加了一个 `sessionProjectTransferContext` 工厂，未调整该业务逻辑或其断言。
