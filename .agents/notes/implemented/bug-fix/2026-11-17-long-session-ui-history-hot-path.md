# Agent Note: 长会话运行时不反复搬运整份界面历史

Status: implemented

## Problem

现场会话原始记录约 137 MiB，界面历史约 71 MiB。每批 `message_end` 会重写完整界面历史，并为了补少量用户消息 ID 拉取含正文的完整会话快照。日志记录到历史 IPC 单次 1.1 秒、渲染进程工作集约 1.93 GiB 和多次渲染探测超时。询问卡答复后还等待草稿删除。

## Decision

- 仅当可见的用户消息还缺定位字段时，沿同一会话当前分支读取用户 ID、时间戳。合并同会话在途查询，不生成正文投影；完整历史读取仍使用原入口。推理耗时随批读取与写入 localStorage，不逐行重新解析存储。
- 完整历史仍是原 JSONL。实时写入按会话合并 250 ms 内的更新；以内存中未变化的记录为前缀、以磁盘回执验证 UTF-8 字节偏移，序列化并发送变化尾段。纯追加不搬旧正文；替换走同路径队列、用临时文件原子提交。已有 JSONL 可作为冷启动检查点，不迁移、不删减。
- 显式裁剪、重新起底、来源补齐、删除先清未发送的旧批次，再排在已发送的保存之后；读取先排空已知待写。保留[回退后按磁盘为准](2026-10-18-rewind-reloads-session-file.md)和[迁移历史按原根解析](../feature/2026-11-17-session-project-transfer.md)。
- 询问卡等答复回执，不等清理。宿主按原请求 owner、会话及 toolCallId 清草稿，旧清理不覆盖新题；未过回执时禁重复提交。保留[视觉评审](2026-11-17-visual-review-and-goal-lifecycle.md)的确认、失败与取消语义。

## Alternatives considered

- 只把原全量写入延后：改动小且不用增量协议，但每次仍制造几十 MiB 的临时字符串和跨进程副本，长回合里仍会复发。
- 用 SQLite 或新日志格式存界面历史：增量记录与随机替换更直接，但需迁移既有历史、重做裁剪和兼容；原格式已能覆盖正常追加和少见替换。
- 截断或限制并行：可以降低上限，但会丢失历史或改变用户工作流；用户确认两者均须保留。

## Consequences

- 稳态 IPC 和序列化成本取决于变化尾段，而不是完整历史大小；仍允许多项目同时输出。
- 实时 UI 缓存最多合并一个批次，进程异常退出可能漏掉尚未发送的最新 UI 投影，SDK 原始历史未改动。首次后端完整起底仍需全量读取；已有行发生变化时为保留原子替换会复制已有磁盘文件，不在渲染层重新序列化共同前缀。
- 文件版本不匹配时拒绝字节补丁，不把错误偏移应用到其他版本。当前读取与截断契约、旧记录及项目并行数量保持不变。

## Verification

- `npm run ui:check -- long-session-responsiveness visual-review` 通过（14 + 24 项）。单／双项目各约 71 MiB 界面历史，生产模式渲染＋真实点击，后端用桩（答复延迟 40 ms）。点确定到收卡约 45.1／45.9 ms；该阶段渲染进程工作集峰值 432.0／401.1 MiB；历史更新分别发送约 3.7／6.7 KiB 尾段，未重传全文。现场全进程内存不与此渲染夹具直接比较。
- `uiHistory.test.ts`、`uiHistoryService.test.ts`、`uiHistoryService.ordering.test.ts`、询问卡、消息回填及关联 IPC 等定向验证通过；覆盖旧 JSONL 恢复、Unicode 偏移、版本冲突、显式裁剪和删除排序。运行时的分支元数据、后台 owner 与迟到草稿写入由 `piRuntimeService.test.ts` 再筛选 3 项通过。
- 较宽的运行时测试有 15 项失败，移除本次宿主改动的隔离对照复现同样 15 项（会话身份、租约、既有快照断言）；不把该套件报为通过。桌面 `electron-vite build --mode localrun` 以临时配置定向全部输出到隔离目录构建通过，未替换或重启正在使用的应用。
