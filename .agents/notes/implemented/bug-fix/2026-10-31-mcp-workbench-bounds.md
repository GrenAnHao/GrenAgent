# Agent Note: MCP 分栏限制在内容区内并独立滚动

Status: implemented

## Problem

用户反馈 MCP 的嵌套工作台超出外层页面，外框在视口底部被截断。外层内容区有高度限制，但共享 inner 使用 `flex: 1 0 auto`，MCP 分栏还有 480px 最小高度；长服务器目录和工具列表会按内容撑高整个工作台。原有场景只检查横向边界，未覆盖长数据的纵向约束。

## Decision

仅 MCP 页的 body 不承担滚动，inner 可收缩到页头之后的剩余高度。MCP grid 用零最小行高，服务器目录与详情继续各自内部滚动，外框始终在内容区留白之内。其他三页的布局与短窗整组滚动沿用原决定。

## Related notes

- [扩展资源工作台](../../implemented/feature/2026-10-31-extension-workbench.md)：部分重叠，仅取代 MCP 允许内容撑高整页的滚动策略，其他页面和功能契约保留。

已检索滚动、高度及 MCP 工作台相关笔记，其他聊天页的整组滚动属于不同模块，不取代。

## Alternatives considered

- 继续让外层整页滚动实现简单，长内容总能访问；但工作台边框和目录会一起离开可见区域，正是用户反馈的问题，因此 MCP 改为内部滚动。
- 只隐藏外层溢出可以快速遮住越界内容，但底部服务器、工具权限与连接配置无法到达，不能采用。
- 按窗口高度计算固定 max-height 能限制边框，但忽略页头换行、缩放和实际父容器大小；用 flex/grid 的剩余高度约束更直接。

## Consequences

24 台服务器、40 个工具在正常、短窗和窄列中均不撑出外层。目录与详情滚动互不带动，末项和配置摘要可到达，滚动前后外框位置不变。仅 MCP 的中间容器改变收缩规则；技能、命令、规则仍沿用原布局。

服务器目录项不参与纵向收缩，长目录通过自身滚动容纳内容，不把条目压扁。未增加窗口高度计算、ResizeObserver 或固定视口尺寸。

## Verification

- `npm run ui:check -- extensions-workbench`：153 项通过、0 失败，只跑 1/43 个场景。其中新增长目录/工具、四边约束、目录与详情真实独立滚动、末项/摘要可达和外框不动；同场景原有四页功能、草稿、主题与短窗检查继续通过。
- 红灯在 1420×880 下测得外框高度 2458.22px、底边 2614.41px，超过外层留白边界 852px；修复后高度 695.81px、底边正好 852px。1420×430 和 520×430 的外框底边分别为 402px / 410px，均在外层边界内。
- 证据：`.agents/evidence/2026-10-31-mcp-workbench-bounds/`，包含红绿日志、正常/窄短窗浅色实际截图。仅样式和布局收缩属性变化，没有改动 MCP 的状态、配置或权限协议。
