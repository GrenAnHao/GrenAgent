# Agent Note: 空白页整体居中与聊天列响应式比例

Status: implemented

## Problem

用户澄清，问题不在输入框是否贴底，而在收窄窗口后空白页的比例：卡片接近铺满聊天区，标题和输入卡仍偏高。只把空态输入框固定底部没有解决该问题。用户审阅宽窄窗口与两种位置的视觉预览后，明确选择「整体居中」。

## Decision

只有空白会话把欢迎标题和现有输入框组成一组居中；已有消息仍贴底并与消息内容列对齐。同一份 ChatInput 不因宽窄或空态切换重挂载。高度不足时 auto margin 归零，空态整区原生滚动，不裁掉草稿/附件/发送按钮。

空态聊天根作为 inline-size 容器，列宽用 min(calc(100% - clamp(16px, 4cqw, 40px)), 928px)，保留输入列 padding 与编辑器 margin，所以卡片最大 880px。标题、上下间距、输入卡初始高度按聊天区/输入卡的真实宽度缩放，不按窗口宽度；宽窗口侧栏挤窄和小窗口产生相同聊天列宽时，比例必须相同。

标题字号 clamp(20px, 3.8cqw, 30px)，空态正文最小高度 clamp(40px, 8cqw, 72px)。聊天列不超过 620px 时，只收紧空态卡片 padding、间距和圆角；正文用户字号、按钮目标与消息态排版不变。沿用现有 520px 编辑器紧凑阈值，不新增自动折叠侧栏行为。

## Alternatives considered

- 全部草稿固定底部可以保持操作位置一致；但窄列仍会有输入框近满宽、标题偏大的问题。用户看过视觉对比后选择整体居中，因此只在已有消息时保持贴底。
- 按窗口 media query 调整最直观；但侧栏或右侧面板也能挤窄聊天区，窗口宽度不能反映内容实际空间，因此以聊天列容器为准。
- 缩小全部控件和正文能快速降低密度；用户还需要读取模型/模式并操作，且可读字号已有偏好，因此只调整空态留白与初始尺寸，复用既有紧凑显示。

## Consequences

空白页在窗口宽度或侧栏占位变化时保持同一组比例，标题与输入卡不因进入草稿而拆成上下两块。代价是空态取消固定底部；已有消息不采用该居中布局。标题 wrapper 与 seat 均禁止收缩，空间不足时自动外边距归零，空态 root 是唯一外层滚动区，不靠负向偏移居中。

空态专用 data-chat-empty 与容器名称限定样式范围；消息态移除该容器名称，并沿用原初始高度、padding、底部定位和滚轮转发。现有浮层 portal 不变，不增加响应式 JS 状态或自动隐藏侧栏配置。
