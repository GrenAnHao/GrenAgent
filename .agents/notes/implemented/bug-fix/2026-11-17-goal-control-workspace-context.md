# Agent Note: 桌面 Goal 控制从原会话建立工作区上下文

Status: implemented

## Problem

桌面用 `agent_goal_control` 恢复暂停目标时，RPC 直接调用 Goal 控制注册表，绕过交互提示普通入口建立的工作区 AsyncLocalStorage。控制事件能提交并启动模型，但续跑工具拿不到 AgentData 授权端点，也读不到原会话的审批档。现场 JSONL 记录第 15 至 21 轮期间普通读工具被拒，同期授权审计无此会话调用，且没有适用的拒绝规则；拦截发生在授权服务作出判定之前。

## Decision

桌面按路径找到原会话后，通过该 `WorkspaceHandle` 执行 Goal 控制。控制注册表仍校验、串行提交并返回回执；提交后的首次创建或恢复派发通过 owner 提供的启动回调，使用既有的 Goal 工作区配置、原会话身份和上下文。同 ID 回执重放、编辑、暂停及清除不取运行配置。审批和沙箱仍按现行规则执行，不复用一次性人类授权。

## Alternatives considered

- **把端点放进进程级配置**：少一层入口接线，但不同工作区共用进程，端点令牌有工作区归属，不能共用或从别的会话补取。
- **让工具在端点不可用时直执行**：表面上恢复续跑，实际跳过规则和审计。保留失败时不执行的边界。
- **拼一条 `/goal resume` 经 `prompt` 提交**：能利用现有上下文，但会把 typed RPC 的提交回执退化为提示词接收，且无法保留同操作 ID 重放契约。

## Consequences

只在启动一轮前解析原会话运行配置；解析失败由原 owner 暂停已提交的目标，不把提交回执等同于工具已执行。工作区绑定、控制 CAS 和规则优先级不变；不会修改现场会话权限或恢复任务。该接线修复与授权通道超时策略相邻，不改真实规则拒绝和传输故障的既有策略。

## Verification

- 现场 JSONL 与 `tool_audit` 只读对照：恢复后至手动暂停期间有工具拒绝结果，但无该会话的授权审计行。修复前 `goalControlHost.test.ts` 新用例复现派发缺失端点、会话 ID 和 Goal 来源，并回退到 `auto` 档。
- 桌面宿主、真实 SDK、真实授权端点和规则服务的定向 Vitest 72 项通过。SDK 使用确定性模型跑连续两轮，`get_goal` 获准执行，第二轮 `create_goal` 仍命中同一会话的显式拒绝规则，两条决定都入审计；两次送到授权服务的均为原会话的 `full` 档。另验证配置获取失败安全暂停且原提交回执可重放。
- Goal 扩展 `control.test.ts`、`lifecycle.test.ts`、`goal-live.real.test.ts` 27 项通过；桌面 `npm run build` 通过，未替换正在运行的实例。
