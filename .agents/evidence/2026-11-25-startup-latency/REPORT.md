# 冷启动首屏与全库目录：同规模实测（2026-11-25）

**结论：Logo 出现到原来的会话可输入，中位数从 4.20 秒降到 3.18 秒；已有磁盘缓存时为 3.17 秒。** 真实 Electron 恢复了记住的消息，编辑器接受了未发送的测试文本。旧版 7 次都在恢复目标前请求全库列表；新版 12 次都先查单个目标，Logo 开始淡出后才发全库请求。单目标查询为 9–24 毫秒。

| 中位耗时 | 原实现（7 次） | 新版首次建缓存（6 次） | 新版已有缓存（6 次） |
|---|---:|---:|---:|
| 启动进程 → 原会话可输入 | 6.90 秒 | 6.35 秒 | 6.06 秒 |
| Logo 出现 → 开始淡出 | 4.11 秒 | 2.93 秒 | 2.67 秒 |
| Logo 出现 → 完全移除 | 4.56 秒 | 3.38 秒 | 3.12 秒 |
| Logo 出现 → 原会话可输入 | 4.20 秒 | 3.18 秒 | 3.17 秒 |
| 首次全库列表 IPC 自身 | 2.640 秒 | 2.858 秒 | 0.039 秒 |
| 启动进程 → 全列表返回 | 5.87 秒 | 10.16 秒 | 7.04 秒 |

**首次建缓存仍需读取历史，但不再挡住首屏。** 1,458 个合成文件、32 个项目、共 1.66 GiB，返回 365 个可见会话。单独的磁盘计数实测如下：

| 主进程至列表返回的整文件读取 | 文件数 | 字节数 |
|---|---:|---:|
| 缓存为空 | 1,458 | 1,779,111,494 |
| 缓存已有，历史未改 | 1 | 9,647（当前目标） |
| 外部只更新另一会话的标题 | 2 | 693,208（当前目标 + 683,561 字节变更文件） |

更新后的标题在后台列表中正确出现。这里统计的是主进程读会话 JSONL 全文，不含目录遍历、文件状态查询或 SDK 子进程恢复当前会话的读取。没有把获取 365 条元数据的 39 毫秒当作应用冷启动耗时。

**启动仍有波动。** 慢的一轮为 9.92 秒才可输入：创建窗口已花 4.42 秒，打开工作区再花 3.11 秒；单个会话查询仅 19 毫秒，后台列表 49 毫秒。Agent 宿主本来就在建窗时异步启动；旧版等待目录的同时宿主也在初始化，移走 2.64 秒的目录耗时不会带来等额端到端收益。当前样本不证明每次启动更快。控制其他测试构建后再交错运行旧/空缓存/已有缓存各 3 次，Logo 到可输入中位仍为 4.13 / 3.12 / 3.17 秒；进程启动到可输入为 6.69 / 5.92 / 6.08 秒。
