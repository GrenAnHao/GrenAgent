# AgentData Wiki 使用说明

Wiki 正文保存在 Markdown 文件中。知识库具有独立名称、用途和稳定 ID，可以不关联项目，也可以关联多个项目。SQLite 保存元数据、版本、索引和任务；旧 SQL 正文继续保留供兼容迁移和检查。

## 管理工作区

在 Agent 数据工作台打开 **Wiki**，默认显示知识库列表。

- **新建知识库**：填写名称、用途，可选关联项目。允许同名；改名、关联或解绑不会搬动文件，也不会自动扫描或调用模型。
- **原始资料**：上传 `.md` / `.txt`、手动录入，或从已关联项目导入。项目导入先预览，确认时重新核对文件内容；不会写回原项目。同名上传默认是两份独立资料，只有“更新这份资料”才增加原资料的版本。
- **知识页面**：可以直接新建人工页面，不要求先有资料；也可以关联多份资料。保存后默认人工锁定，锁定页仍可人工编辑。
- **开始抽取**：先确认实际资料数量和当前模型，再创建任务。保存资料本身不调用模型。成功且未变化的资料不重复抽取；锁定、多来源或版本冲突的页面会跳过，不覆盖人工内容。

创建任务后留在当前知识库，点击“查看任务”才跳转。切换面板或返回列表会保留工作状态。`Ctrl+S` / `Meta+S` 保存页面，未保存时按 `Escape` 需要确认；版本冲突时草稿保留。

## 文件位置

```text
<应用数据目录>/
├── agent-data.db
└── wiki/<storageKey>/
    ├── library.json          库元数据，删除后保留墓碑
    ├── workspace.json        仅旧库：原工作区及迁移记录
    ├── wiki/                 Markdown 页面
    ├── raw/sources/          按 sourceId / revision 保存的原文快照
    └── legacy-backup/        仅旧库：兼容导出时保留的旧正文
```

逻辑 `kbId` 与物理 `storageKey` 分离。新库使用 `kb-<UUID>` 目录；旧库继续使用原始工作区字符串的哈希目录，不复制或搬动正文。库名和项目路径都不参与新库的物理目录命名。管理工作区提供打开存储位置和页面位置的入口。

新版 frontmatter 保存 `kbId`、`pageId`、`title`、`sourceRefs`、`revision`、`updatedAt`、`locked` 等字段。旧字段继续兼容。页面版本比较包含完整 Markdown 文件（含 frontmatter）的 SHA-256，哈希不写入自身。

可直接编辑磁盘正文；希望保留人工版本时，将 `locked` 设置为布尔值 `true`，不能写成字符串 `"true"`。应用会检测已观测到的外部修改和应用内并发，但不承诺消除所有外部程序在最终检查与文件替换之间的操作系统级竞争。

## Agent 工具

| 工具 | 用途 |
| --- | --- |
| `wiki_list` | 不传 `kbId` 列出当前项目关联库；传 `kbId` 列出该库页面 |
| `wiki_search` | 检索当前项目显式关联的知识库，可限定 `kbId` |
| `wiki_read` | 使用列表或检索返回的 `kbId`、`pageId` 读取正文 |
| `wiki_update` | 仅更新旧 workspace 原映射库；从源文件生成，会调用模型 |
| `wiki_reindex` | 仅重建旧 workspace 原映射库索引，不调用模型 |

新建具名库本阶段向 Agent 开放关联读取；写入通过管理页人工保存或显式抽取。未关联库只能在全局管理页管理，解绑立即生效。项目凭据由主进程签发，Agent 不能通过伪造 workspace、管理参数或通用任务命令扩大 Wiki 权限。

旧 `wiki_update` / `wiki_reindex` 仍检查 Electron 权限，只读模式不执行。旧写工具在生成前读取页面版本，过期结果安全跳过；如果资料已被独立人工更新，则保留该版本，等待明确抽取。取消、模型错误、截断和空结果不会覆盖已有页面。

## 删除与恢复

三种删除的影响不同，确认框会显示稳定目标及影响范围：

- 删除资料：保留引用它的页面及所需版本快照，来源标为已删除。
- 删除页面：保留资料并抑制自动再生成；更新原文也不会恢复。需要时明确选择“重新生成”。
- 删除知识库：移除该库正文、快照和项目关联，保留旧 SQL、迁移备份、库墓碑、审计与任务历史，不删除项目原文件。

删除先阻止新写入，再等待实际写入任务结束。无法取消的系统任务显示等待，不能把点击取消当成已经终止。“待完成的删除”保留重新处理入口。关闭数据运行时会等待已启动任务收尾；重启后中断的 Wiki 抽取记录保留并标明中断，不自动重放模型调用。

## 手工修改与迁移

外部修改 `.md` 后，在知识库“更多”中重建索引（旧库也可使用 `wiki_reindex`）。这不调用模型、不改正文、不清人工锁。通过管理页保存时索引同步更新；外部修改后需要重建才能更新检索结果。

兼容迁移先保留原 SQL→Markdown 导出流程，再为已存在目录登记稳定知识库 ID；不会重复复制正文。已有文件不覆盖，同 ID 冲突旧正文保留在 `legacy-backup/`。解绑和删除不会因重跑登记而恢复。不要手工清理 `library.json`、`workspace.json` 或迁移回退表。

重建结果中的 `diagnostics` 非空时，检查提示的文件：损坏元数据或无法读取的工作区会保留旧索引；修复文件后再次重建。文件或数据库写入失败时会保留旧版本；极端情况下恢复本身失败，旁边的 `.rollback` 文件仍保存旧正文，先备份再处理。

## 本次范围

本阶段实现独立知识库、多项目关联、资料版本、人工页面、显式单来源抽取、安全删除和管理工作区。未引入多租户系统、实体关系图、多跳搜索或自动多来源知识合并；多来源人工页由用户维护。

开发版需要重启 Electron 和 sidecar 才会加载新扩展；发行版需要重新打包。构建和测试不会自动重启正在使用的应用，也不会主动迁移真实数据。
