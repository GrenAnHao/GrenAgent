# 会话活动：回复、压缩与子代理状态

回复和上下文压缩是独立活动。准备和运行时，对话时间线用一条带转圈的分隔线显示压缩状态，输入区不再重复提示。即使没有流式回复，所属会话的侧栏仍有运行标记。普通回复结束不代表压缩结束；发出停止请求也不等于已经停止，界面等 SDK 的真实终态确认。

切换会话不会把原会话的压缩状态带到另一会话。窗口重新加载时，从仍存活的宿主读取实际活动；不会把磁盘里的历史压缩记录当作正在运行，也不会保存一个 `compacting=true` 并在宿主退出后重放。无法确认时，分隔线显示「暂时无法确认压缩状态」并停止旋转；成功时，同一位置留下「上下文已压缩」。

压缩完成后，界面按原会话和宿主的上下文版本重新读取实际用量。即使完成时该会话在后台，切回后也会核对版本；压缩前的旧统计响应不能覆盖新结果。刷新期间可保留最后已知用量，但不会把统计失败改成零，也不承诺每次压缩后数值一定降低。

自动压缩触发的内部中断不作为请求失败展示；明确的用户停止、准备失败、摘要失败和其他真实错误仍会显示。手动压缩及停止绑定发起时的会话，不会因等待期间切换前景而操作另一会话。本次不改变压缩阈值、摘要和原有续跑策略。

子代理尚未返回路径时显示启动中；已登记但没有首响应时显示等待首响应。列表没有记录、记录超过列表窗口或临时读取失败，只能说明状态尚待确认，不能据此判定孩子中断。共享查询会自动退避对账，不需要点击人工重试；自动恢复仅重查状态，不重启孩子。

单卡、并行组、列表和详情沿用同一可信状态。明确完成、失败、停止或中断及时收口，不被迟到空查询改回运行。停止和中断不是请求失败。父工具已返回也不代表孩子已完成；孩子回复之后仍有后台 Bash 的等待、超时和真实结算继续遵循原规则。
