## 背景
压测时上游偶发慢请求，池子被占满导致整体 p99 抖动。当时的直觉是改成按需扩容。

## 决定
保持固定大小，改为对慢请求加超时熔断。

## 放弃的方案
- 弹性伸缩：冷启动带来的抖动反而打穿上游超时，实测 p99 从 40ms 涨到 300ms。
- 每任务新建线程：内存峰值不可接受，且线程创建开销大于收益。

## 后果
并发上限写死，需要改配置才能调整。若将来单机内存压力缓解，可重新评估弹性方案。
