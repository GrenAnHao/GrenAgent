# Edit 预览改进设计

- 日期：2026-08-27
- 状态：设计待评审
- 范围：`tauri-agent/src/features/tools/ToolExecution.tsx` 的 edit 工具详情渲染

## 目标

修复 edit 详情只显示固定高度前几行、修改位置不可见、路径过长和替换未生效时信息不清的问题。用户应能快速看到修改点，并在需要时滚动查看完整内容。

## 设计

### 1. 编辑结果数据

- 优先使用工具结果中的 `details.diff`，因为它代表实际应用结果。
- 没有 diff 时，从 `oldText`/`old_string` 和 `newText`/`new_string` 构造预览。
- 当结果文本包含“replacement produced identical content”等提示时，保留原文并以错误状态渲染，不伪造成功 diff。
- 编辑组件不负责执行替换；文件写入仍由后端 edit 工具完成。

### 2. 预览窗口

- 根据 diff 的修改行计算最小上下文窗口：修改区域前后各 5 行；窗口到达文件边界时缩短。
- 多个修改块分别保留上下文，合并重叠窗口，避免重复行。
- 代码区域使用单个可滚动容器，设置有限最大高度；支持纵向和横向滚动。
- 滚动条使用细、透明轨道、悬停/聚焦时显示的低对比度样式。
- 显示行号和 `+`/`-` 标记，修改行使用增删颜色区分。
- 提供“显示完整文件/仅显示修改上下文”切换；默认显示上下文窗口。

### 3. 文件名与语言

- edit 标题和详情只显示 basename，例如 `GeminiProvider.ts`。
- 完整路径作为悬停提示和可访问名称保留，避免信息丢失。
- 根据文件扩展名调用现有 `langByPath`，使用 `LazyHighlighter` 渲染 TypeScript、TSX、JavaScript 等代码。
- diff 的增删标记由 diff 高亮处理，代码内容使用目标文件语言；若无法拆分则回退为 diff 语言。

### 4. 空替换错误

- 后端返回“内容未变化”时，前端明确显示失败状态和完整错误文本。
- 不把 `oldText`/`newText` 相同的请求显示成成功修改。
- 结果没有有效文本或 diff 时，沿用现有 JSON/终端回退渲染。

## 测试与验证

- 为 edit 详情增加测试：上下文包含修改点前后各 5 行；长内容可滚动；文件名显示而非完整路径；按 `.ts` 使用 TypeScript 高亮；空替换错误可见。
- 保留现有 read/write/bash/tool 标题测试。
- 运行 `bun test`（或项目现有测试命令）和 `bun run build`，确认 TypeScript 与 Vite 构建通过。

## 非目标

- 不改后端 edit 的替换算法、路径解析或错误文案。
- 不引入新的代码高亮库；复用项目已有 `@lobehub/ui` 高亮组件。
- 不调整其他工具的详情布局。
