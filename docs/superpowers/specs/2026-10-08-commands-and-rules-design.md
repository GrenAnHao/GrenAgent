# 命令与规则系统设计

日期：2026-10-08
状态：设计已确认，待写实现计划

## 目标

- **命令**：全局注册的预置提示词，由名字和正文组成。在输入框打 `/` 能选出来；正文里用 `{参数}` 留空，输入框把命令和参数渲染成一个可编辑的胶囊，`Tab` 在参数之间切换。
- **规则**：分全局和项目两级，可以有多条，每条单独开关。启用的规则在每次发送对话时自动放进上下文。

## 已定的方向

| 决策 | 结论 |
|---|---|
| 存储底座 | 复用 Pi 原生：命令就是 prompt template；规则用 Pi 的 context files 通道注入 |
| 规则形态 | 多条列表：一条一个 `.md` 文件，可以单独开关 |
| 输入框形态 | 命令和参数合成一个整体胶囊，正文不在输入框里显示 |
| 发送后的气泡 | 只显示同一个胶囊（只读），展开后的正文只给模型看，气泡里没有展开入口 |
| 胶囊视觉 | 外层是圆角矩形（7px），铺满命令底色；只有参数是嵌在里面的圆角矩形（4px），见下文「视觉规格」 |
| 默认值 | 支持 `{名=默认值}` |
| 管理入口 | 扩展面板新增「命令」「规则」两个页签 |
| 胶囊实现 | Lexical DecoratorNode 加内嵌 `<input>`，沿用 ChatTagNode 的模式 |

## 现状依据

- Pi 的 prompt templates 从 `<agentDir>/prompts/*.md` 加载成 `/命令`，自带 `$1`、`$@`、`${1:-默认}` 这类位置参数。它的参数解析（`parseCommandArgs`）只认引号，**不支持转义**。
- 斜杠菜单已经把 prompt template 列在「提示词」组（`apiSource: 'prompt'`），选中后插入 ChatTag 命令 chip。
- Pi 存进会话的是展开后的文本。技能的做法是把 `/skill:x` 展开成 `<skill name=…>…</skill>`，气泡渲染时由 `messageTags.tsx` 折回 chip。本设计让命令照这个做法实现。
- `input` 事件在模板展开之前触发，可以返回 `{ action: "transform" | "handled" | "continue" }`。
- `before_agent_start` 可以改 `systemPromptOptions.contextFiles: Array<{ path, content }>`，和 AGENTS.md 走同一个段落。
- 已有的 `extensions/rulebook`（`.pi/rules.jsonc`）管的是工具拦截和跑偏纠正，和本设计的「规则」是两回事。为了避免混淆，新扩展起名 `context-rules`。

## 一、单元划分

| 单元 | 位置 | 职责 | 依赖 |
|---|---|---|---|
| 语法模块 | `extensions/prompt-commands/syntax.ts` | 纯函数：解析占位符、参数序列化/反序列化、构造和解析 `<command>` 块 | 无 |
| `prompt-commands` 扩展 | `extensions/prompt-commands/index.ts` | `input` 钩子：识别 `/名字 参数…`，读模板、代入参数、包成 `<command>` 块 | 语法模块、Pi agentDir |
| `context-rules` 扩展 | `extensions/context-rules/` | `before_agent_start` 时读取启用的规则，追加到 `contextFiles` | Pi agentDir、cwd |
| 主进程服务 | `electron-agent/electron/app/promptLibraryService.ts` | 命令和规则的列表、读取、保存、删除 IPC；负责校验和原子写入 | 语法模块（推导参数、生成 `argument-hint`） |
| 管理界面 | `electron-agent/src/features/extensions/CommandsPanel.tsx`、`RulesPanel.tsx` | 两个新页签，左边列表、右边编辑 | IPC |
| 输入框胶囊 | `electron-agent/src/features/chat/input/editor/CommandPill/` | `CommandPillNode`、`CommandPillPlugin`、`CommandPillView`（可编辑和只读两种模式） | 语法模块 |

渲染层通过已有的 `@extensions` 别名引用语法模块，扩展和界面共用一份，不各写一套。

## 二、文件格式

### 命令

只有全局一份，路径是 `<agentDir>/prompts/<name>.md`，格式仍然是合法的 Pi prompt template：

```markdown
---
description: 按指定风格重构文件
argument-hint: "<file> [style]"
---
请把 {file} 重构成 {style=functional} 风格，保持行为不变。
```

- `argument-hint` 由保存逻辑根据占位符自动生成：必填参数写成 `<名>`，有默认值的写成 `[名]`。这样 CLI 补全也能显示参数。
- **占位符语法**：`{标识符}` 或 `{标识符=默认值}`。
  - 标识符的正则是 `[\p{L}_][\p{L}\p{N}_-]*`：以字母、中文或 `_` 开头，后面可以跟字母、数字、`_`、`-`。所以 `{"a":1}`、`{ }`、`{1}` 都不算占位符。
  - 默认值是 `=` 到下一个 `}` 之间的文本，不能包含 `}` 或换行。
  - `{{` 和 `}}` 是转义，分别输出字面量 `{`、`}`，比如 `{{file}}` 输出 `{file}`。
  - 同名占位符算一个参数；参数顺序按首次出现的位置排；某个参数只要有一处写了默认值，就以第一个默认值为准。
  - 没有默认值的参数必填。
- **命令名**就是文件名，正则 `^[\p{L}\p{N}][\p{L}\p{N}_-]{0,63}$`。和内置、扩展、技能命令或已有模板重名时不让保存（改名到自己原来的名字除外）。
- 正文里没有 `{}` 占位符的模板（包括手写的 `$1` 写法）由 Pi 原生处理，本系统不接管，只在管理界面里显示和编辑。

### 规则

- 全局规则放在 `<agentDir>/rules/*.md`，项目规则放在 `<工作区>/.pi/rules/*.md`。

```markdown
---
title: 中文回答
enabled: true
---
- 回复一律使用简体中文
- 代码标识符保持英文
```

- 文件名在新建时由标题生成一次：先清成 `[\p{L}\p{N}_-]`，重名就加 `-2`、`-3`。之后改标题不改文件名。
- frontmatter 里缺 `enabled` 视为 `true`；缺 `title` 时用文件名。
- 和 AGENTS.md 一样，项目规则不需要项目信任就会加载。

## 三、数据流与交互

### 输入框

1. 打 `/` 打开菜单，「提示词」组里的模板后面显示参数提示，例如 `{file} {style}`。
2. 选中带占位符的模板：插入 `CommandPillNode`，参数全空，焦点落在第一个参数。选中不带占位符的模板：照旧插入 ChatTag。
3. 胶囊里的键盘行为：

| 按键 | 行为 |
|---|---|
| `Tab` | 跳到下一个参数；在最后一个参数上按，跳出胶囊，光标落到胶囊后面的正文里 |
| `Shift+Tab` | 跳到上一个参数；在第一个参数上不动（胶囊之前不允许有内容） |
| `Backspace`（参数为空） | 回到上一个参数；在空的第一个参数里再按一次，删除整个胶囊 |
| `←` / `→` 走到参数边界 | 移到相邻参数；在最后一个参数末尾按 → 移出到胶囊后面；第一个参数开头按 ← 不动 |
| `Esc` | 跳出胶囊，光标落到胶囊后面 |
| `Enter` | 发送。有必填参数空着时不发送，焦点跳到第一个空着的必填参数，这个参数抖一下 |
| 粘贴 | 参数里的换行压成空格 |

4. 在编辑器里粘贴 `/refactor "a" b` 这样的文本，如果命中带占位符的模板，就生成填好参数的胶囊。这是在 `useCommandPaste` 上扩展出来的。
5. 一个输入框最多一个胶囊，而且必须放在整个输入的最开头，因为扩展只认以 `/名字` 开头的文本。斜杠菜单只在 `/` 位于整个输入开头时，才列出带占位符的模板；在第二行行首等其他位置打 `/` 时，菜单里不出现这些模板。粘贴识别也遵守同一条限制。

### 发送

- 胶囊序列化成 `/refactor "src/a.ts" "functional"`：
  - 所有参数都加双引号，值里的 `"` 写成 `\"`，`\` 写成 `\\`。
  - 空着的参数发 `""`。
  - 胶囊后面的正文用一个空格接在最后一个参数后面。
- 扩展的 `input` 钩子收到文本后：
  1. 不是以 `/名字` 开头，或者找不到对应模板，或者模板里没有 `{}` 占位符 → 返回 `continue`。
  2. 用支持转义的解析器按顺序取 N 个参数（N 是参数个数），剩下的原文是补充正文。
  3. 空参数换成默认值。还有必填参数缺失时，`ctx.ui.notify` 报出缺哪几个，返回 `handled`，不发出去。这种情况只会在 CLI 手打时出现，App 在输入框里就拦住了。
  4. 代入后返回 `transform`，文本格式如下：

```text
<command name="refactor" args="{&quot;file&quot;:&quot;src/a.ts&quot;,&quot;style&quot;:&quot;functional&quot;}">
请把 src/a.ts 重构成 functional 风格，保持行为不变。
</command>

<补充正文，没有就省略这一段>
```

  - `args` 是参数名到值的 JSON 对象，按 HTML 属性规则转义 `& " < >`，键的顺序就是参数顺序。
  - 模板正文里的字面量 `</command>` 转成 `<\/command>`，防止块被提前截断。
- 发出去时，图片照原样传下去。

### 气泡

- `messageTags.tsx` 识别 `<command name=… args=…>…</command>` 块，整块只渲染成只读胶囊，块内正文不显示，也没有展开入口。块后面的补充正文按普通文本渲染，文件引用和链接照旧识别。
- 刚发出去的消息里还是 `/名字 "参数"…` 原文。气泡用命令缓存（`loadCommands`）判断这是不是带占位符的模板，是就同样渲染成胶囊。判断不了时按普通文本显示。

### 规则注入

- `context-rules` 在每次 `before_agent_start` 时读一遍规则目录，按文件 mtime 缓存解析结果。
- 排序规则：全局在前、项目在后；同一范围内按文件名排序。
- 只注入启用的规则，每条追加一项 `{ path: 规则文件绝对路径, content: 正文 }` 到 `systemPromptOptions.contextFiles`。
- 规则不变时系统提示也不变，不会打掉前缀缓存。改了规则，下一轮生效，不需要重载。
- 子代理同样加载这个扩展，所以规则也会进子代理的上下文，和 AGENTS.md 的行为一致。

### 管理界面

- 扩展面板的页签变成 MCP ｜ 包 ｜ 技能 ｜ 命令 ｜ 规则。
- **命令页**
  - 左边：列表，每项是命令胶囊，有参数的显示「N 参数」。
  - 右边：编辑区，字段依次是命令名、描述、提示词。提示词编辑区里高亮 `{占位符}`，下面实时列出识别到的参数（序号、名字、默认值）。
  - 底部：保存和删除按钮。
- **规则页**
  - 左边：列表，顶部可以按全部、全局、项目筛选，每条规则带开关和范围标记。列表底部注明 Pi 自己还会读 AGENTS.md / CLAUDE.md，这里不管它们。
  - 右边：编辑区，字段是名称、范围（全局或项目）、Markdown 正文。
  - 开关直接改 frontmatter 并立即写盘。
- 没有打开工作区时，「项目」范围置灰，提示先打开工作区。
- 命令保存或删除后，调用扩展面板现有的 `markChanged`，提示用户重载会话来拿到新模板。规则改动不需要提示。

## 四、视觉规格

胶囊在输入框（可编辑）和气泡（只读）里用同一个 `CommandPillView`。本文的「胶囊」是这个命令组件的名字，不代表形状：它的实际形状是圆角矩形。

- **外层**：圆角矩形，`border-radius: 7px`，没有边框，整体铺满命令底色 `color-mix(紫, 22%, transparent)`。除了参数块，其余空位全是这个颜色。内边距是上 3px、右 3px、下 3px、左 9px；没有参数时右边也是 9px。子项间距 4px。
- **命令名**：命令图标加命令名，直接写在外层底色上，没有自己单独的底块。字重 600，文字用紫色。
- **参数段**：嵌在外层里的圆角矩形，`border-radius: 4px`，左右内边距 7px，是唯一有独立形状的部分。参数名写在值前面，字号 11px，颜色在紫色和次要文字色之间。参数段底色比外层深，用 `color-mix(背景色, 55%, transparent)`，在紫色底上能看出来。
- **参数段状态**
  - 焦点：1px 描边，用 `colorPrimary`；底色是 `color-mix(colorPrimary, 14%, transparent)`。
  - 空着：显示默认值或参数名作占位，灰色斜体。
  - 必填参数缺失时被拦截：参数段抖一下，描边换成 `colorError`。
- 输入框里的参数 `<input>` 宽度随内容变化，最小宽度等于占位文字的宽度。
- 气泡里的参数值超过 32 个字符就截断，悬停时显示完整值。
- 「紫」用 `cssVar.purple`，和现有的命令 chip 同一个变量，明暗主题都跟着变。

## 五、错误处理

| 场景 | 处理 |
|---|---|
| 规则文件读不出来，或 frontmatter 解析失败 | 注入时跳过这条并写日志；管理列表里这条标警告，悬停显示原因 |
| 命令名不合法或重名 | 在编辑区就地报错，保存按钮不可用 |
| 写文件失败 | 走原子写入（先写临时文件再改名），失败时提示，不留半截文件 |
| 扩展读模板失败 | 返回 `continue`，交给 Pi 原生处理，不吞掉用户的输入 |
| CLI 手打时缺必填参数 | notify 报缺哪几个参数，返回 `handled` |
| `<command>` 块的 `args` 解析失败 | 气泡退回普通文本显示 |

## 放弃的方案

- **自建 JSON 存储加 `registerCommand`**：会和 Pi 原生的 prompts、AGENTS.md 并存两套机制，CLI 和 App 看到的也不一致。
- **规则直接编辑两份 AGENTS.md**：没法对单条规则开关。用户选了多条列表。
- **输入框里展开正文、正文中嵌填空块**：用户选了更紧凑的命令胶囊加参数槽。
- **气泡显示展开后的全文**：长模板会把对话撑得很长，也看不出这是哪条命令。
- **前端代入参数后直接发全文**：做法同上一条，而且 CLI 用不了带名字的参数。
- **用 ElementNode 加原生 TextNode 实现胶囊**：要处理大量规范化问题，和 @lobehub/editor 的快捷键插件也容易冲突。
- **参数做成输入框外的一排表单**：违背了一体化胶囊的方向。
- **用 `systemPrompt` 整体替换来注入规则**：会绕开 Pi 的分段机制；用 `contextFiles` 和 AGENTS.md 同路，更简单。

## 不在范围内

- 项目级命令
- 按路径、文件类型等条件生效的规则
- 规则拖拽排序、优先级
- 命令和规则的导入导出与分享
