# 会话消息编辑与回退

- 日期：2026-09-22
- 修订：2026-09-22 按已确认原型锁定操作栏。编辑占原「移出上下文」的位置，不悬浮到气泡外。
- 状态：待审查
- 范围：GrenAgent 桌面端主对话（`electron-agent`）
- 主题：桌面端编辑最后一条用户消息，以及把当前上下文中的用户消息回退到输入框。旧内容从画面、界面历史和本地会话里删除，不留旧分支。

## 1. 背景与现状（已核对到代码）

**已存在**

1. 「回退到此」已在消息操作栏上，但实现是 fork：`agent_rewind_to` 按 timestamp 在会话文件里找 entryId（`electron/app/piRuntimeService.ts:206`、`:827-849`）→ `handle.fork(entryId)`（`:507`）→ 新分支，旧路径留在原文件。前端 `store.rewindTo` 调完再拉一次消息（`src/stores/agent.ts:289-294`）。
2. 「编辑」是禁用占位（`src/features/chat/messageActions/slots.tsx:36`）。
3. 上下文控制动作当前**同时挂在用户消息和助手回合上**（`src/features/chat/UserMessage.tsx:71`、`src/features/chat/TurnTimeline.tsx:132`）。把回退收窄到用户消息是行为收窄，不是纯新增。
4. 悬浮操作栏在**流式进行中整条不渲染**（`src/features/chat/messageActions/MessageActionBar.tsx:79-81`、`:111`），注释写明原因：回退（fork）/移出上下文会与在跑的回合抢状态。所以「运行中也能点」必须改这条门控，且必须自带「先停回合」的时序。
5. 界面另存一份更长的历史 `<workspace>/.pi/ui-history/<key>.jsonl`：每轮结束覆盖写、fire-and-forget（`src/stores/agent.ts:133-145`）；重载时只要它比后端长就**用它**（`:217-219`）。只删画面不截这份文件，重开会把已删消息显示回来。

**决定本次能否落地的前置约束**

6. **前端没有消息标识。** 本地插入的用户消息不带 timestamp（`src/stores/agentReducer.ts:557-575`），而操作栏要靠 `ctx.timestamp != null` 才启用上下文动作（`MessageActionBar.tsx:127`）。结果是：刚发出去的、最需要被编辑的那条用户消息，当前**连入口都没有**。回退/编辑首先要解决「怎么指认这条消息」。
7. 现有 timestamp→entryId 是「全文件扫描、取**最后一条**匹配」（`piRuntimeService.ts:829-849`），不限定活动分支；fork 过的会话里同一 timestamp 会出现多次。把它当定位键不稳。
8. **pi 侧没有就地删条目能力。** RPC 命令面没有 `navigate_tree`，也没有任何截断/删除命令（`extensions/node_modules/@earendil-works/pi-coding-agent/dist/modes/rpc/rpc-mode.js:298-542`）；SDK 的 `SessionManager` 只有 `branch()`（移 leaf）和 `createBranchedSession()`（另存新文件），文档明写 "allowing new branches without modifying history"（`.../dist/core/session-manager.d.ts:211-221`），无删除 API（`.../docs/session-format.md:455-482`）。要满足目标 4，只能由宿主改写文件。
9. **leaf 是隐式的**：加载时 `leafId` 取文件里**最后一行**的 id（`.../dist/core/session-manager.js:732-753`，`getLeafId()` 在 `:1002`）。截断即删行，leaf 自动落到剩下的最后一行——这是本方案成立的前提，也是它的限制（见 §3 截断不适用）。
10. 让 pi 重新读盘有现成原语：`WorkspaceHandle.reload()` = `waitForIdle()` + `session.reload()`（`electron/agent/workspaceHandle.ts:150-155`）。但 `WorkspaceHandlePort`（`piRuntimeService.ts:54-55`）没有暴露 `reload`，要加。
11. `session.navigateTree()` 在回合进行中会 reject（`.../docs/sdk.md:116`）。本设计不用它，但同一约束适用于任何会话树改写。

**结论**：不用 fork 是对的，但理由要换（见 §3）；且必须新增「消息标识」通道与「主进程截断命令」两件事，否则目标 1、2 无处落地。

## 2. 目标 / 非目标

**目标**

1. 对话停下时，可以编辑最后一条用户消息。
2. 当前模型上下文里的用户消息可以回退，运行中也可以。回退先确认。
3. 沿用现有消息悬停操作栏，图标在气泡下方右对齐，不悬浮到气泡外侧。常驻图标顺序为回退、编辑、复制，加「…」菜单。去掉「移出上下文」，编辑占它原来的位置。菜单为：复制、回退到此、编辑、重新生成、删除。编辑、重新生成、删除不再标「即将支持」。
4. 被去掉的内容从当前画面、界面历史和本地会话文件中删除。重新打开会话不再出现。
5. 回退确认之后的发送，以及编辑完成删除之后的发送，都是普通发送。

**非目标**

- 不退回工作区文件，不做文件快照。工作区文件在全部路径上保持不动。
- 不编辑助手回复或工具结果。
- 不回退压缩摘要之前、只存在于界面历史里的用户消息（`get_messages` 投影里没有的条目）。
- 不清理已被删内容在**压缩摘要**里的残留表述。摘要按生成时的内容保留，删掉该条不会改写摘要（接受）。
- 不在对话进行中编辑。
- 不自动发送。
- 编辑框里的 `/` 不提供技能以外的斜杠命令。
- 不删除尚未进入会话的引导或跟进队列。编辑进行中不改底部输入框里尚未发送的草稿，取消后它仍在。回退确认成功，以及编辑在截断成功但发送失败之后，会用该条文字替换底部草稿。
- 不改 CLI / Web 的消息操作面，不做多分支会话的树浏览。
- 不把铅笔或回退图标悬浮到气泡外侧。入口只用现有悬停操作栏。
- 不再提供「移出上下文」或「恢复到上下文」。

**成功标准**

对话停下时，仍在当前上下文里的最后一条用户消息能就地变成输入框。取消不删除。发送后旧内容从画面、界面历史、本地会话三处一起消失。运行中的回退能停下回合、删掉该条及其后、把原文放回底部输入框，且重开会话看不到旧内容。发给模型的历史与画面上剩下的一致。工作区文件全程不变。

## 3. 已确认的设计决定

| 维度 | 决定 |
| --- | --- |
| 消息标识 | 用**会话条目 id（entryId）**，不用 timestamp。后端 `agent_get_messages` 改为返回带 provenance 的投影（entryId + 是否在当前上下文），前端 `ChatMessage` 增 `entryId` |
| 编辑入口 | 现有操作栏里，占原「移出上下文」的位置，铅笔图标。活动分支上最后一条用户条目，且对话停下，且该条仍在当前上下文里。无二次确认弹窗 |
| 回退入口 | 现有操作栏第一项「回退到此」。活动分支上、且在当前模型上下文里的用户消息。运行中也能点。必须确认。确认框只有确认和取消 |
| 移出上下文 | 从操作栏和菜单移除。不再提供移出或恢复。已排除的旧消息仍视为不在当前上下文，没有编辑和回退 |
| 重新生成 | 只用于已经停下、且已有后续回复的最后一条用户消息。保留原文，删掉它后面的内容，用原文再发一次 |
| 删除 | 当前上下文中的用户消息。确认后删掉该条及其后内容，不放入输入框 |
| 输入 | 编辑按钮为铅笔图标，悬停最后一条可编辑用户消息才显示。编辑框是铺满内容列的简化底部输入框：文字、图片、拖入文件/文本/图片，`/` 只弹出技能，`@` 与底部输入框相同。只有发送和取消，没有模型、模式、审批和其它底部动作。取消则消息块恢复，不删除。回退确认后，以及编辑在截断成功但发送失败之后，文字都在底部输入框 |
| 编辑删除时机 | 在那条消息变成的输入框里按下发送时：先取走文字 → 截断 → 发送这份文字。取消不截断 |
| 回退删除时机 | 确认后：先记住文字 → 停止正在跑的回合 → 截断 → 放入输入框 |
| 回退确认后的发送 | 普通发送。输入框里的文字可以先改 |
| 取消回退确认 | 画面、会话和正在跑的回合都不变 |
| 失败回填 | 截断失败：消息块仍在，停留在编辑输入，文字不丢，不发送。截断成功但发送失败：接受不回滚；消息块已移除，文字放回底部输入框，之后按普通发送，不再删除 |
| 停止回合 | 与截断放在同一次主进程调用里：`abort()` → `waitForIdle()` → 截断 → `reload()`。前端不编排这段时序 |
| 存储 | 截断由主进程原地改会话文件：按 parentId 删后代闭包 + 原子重写；界面历史同步写成同一份剩余对话 |
| 不用 fork 的理由 | fork 会换会话文件与会话 id（新会话行、界面历史 key、草稿 key 全变），与「同一条会话原地截断」不符。fork 后删旧文件虽也能不留旧内容，但会话身份已换 |
| 截断不适用时 | 目标条目的后代集合 ≠ 文件里位于它之后的全部行（历史遗留多分支）→ 拒绝并提示，不删除 |
| 界面历史写失败 | 写失败则删掉该会话的 ui-history 文件（`ui_history_delete` 已有，`src/lib/pi.ts:337`），下次加载回落到已截断的后端，绝不保留更长的旧历史 |
| 待发送意图 | `idle` / `edit-pending` / `rewind-loaded` 三态，见 §4 |
| 编辑未发送又回退 | 以回退为准，丢弃 `edit-pending`，按回退规则立即删除 |

对话进行中，指当前回合还在跑，包括正在生成和工具仍在执行。对话停下，指没有这样的回合。

## 4. 待发送意图状态机

「编辑点过但没发送」「回退刚把文字放回输入框」这两种待发状态必须互斥，否则会出现「多发一次删除」或「删完又删」。

| 当前态 | 事件 | 新态 | 动作 |
| --- | --- | --- | --- |
| idle | 点编辑 | edit-pending | 该条消息变成输入框，原文在其中；会话不删 |
| edit-pending | 取消 | idle | 输入框收回，消息块恢复，不删除 |
| edit-pending | 按下发送且截断失败 | edit-pending | 不发送；消息块保持为输入框，文字仍在 |
| edit-pending | 按下发送且截断成功、发送失败 | rewind-loaded | 不回滚。消息块已移除，文字放入底部输入框。之后发送不再删除 |
| edit-pending | 按下发送且发送成功 | idle | 截断后发出取走的文字 |
| edit-pending | 确认回退 | rewind-loaded | 丢弃 edit-pending，按回退规则执行 |
| edit-pending | 点其它消息的回退并取消确认 | edit-pending | 什么都不做 |
| idle | 点回退并确认 | rewind-loaded | 停回合 → 截断 → 文字入框 |
| rewind-loaded | 按下发送 | idle | 只发送输入框当前文字，**不再删除** |
| 任意 | 切换会话 / 回到空会话 | idle | 丢掉待发送意图，不做删除 |

## 5. 行为

### 5.0 操作栏

用户消息悬停后，图标在气泡下方右对齐，顺序为：回退、编辑、复制、更多。菜单为：复制、回退到此、编辑、重新生成、删除。没有「移出上下文」，也没有「即将支持」。助手消息不提供回退、编辑、重新生成、删除。

回合进行中，操作栏仍可出现回退。编辑、重新生成、删除在进行中不出现。

### 5.1 编辑

1. 在现有悬停操作栏点铅笔，位置是原来的「移出上下文」。该条消息 item 就地换成输入框，宽度铺满对话内容列。它是底部输入框的简化版：可输入文字、放图片，并可拖入文件、文本和图片，拖放提示与底部输入框相同。输入 `/` 只弹出技能调用；输入 `@` 弹出和底部输入框相同的选项。按钮只有发送和取消，没有模型、模式、审批和其它底部动作。会话和其它消息先不动。
2. 取消：输入框收回，消息块恢复，不删除。
3. 按下发送：先取走输入框里的文字，再删除这条用户消息和它后面的内容，再发送这份文字。
4. 截断失败：不发送。消息块保持为输入框，文字仍在，并提示。
5. 发送失败（截断已成功）：不回滚。消息块已移除，文字放入底部输入框，可以再按发送。这次发送不再删除。
6. 入口消失条件：回合开始跑、这条已不在当前上下文、或这条已不是活动分支的最后一条用户条目（例如期间又发了消息）。正在编辑时若入口消失，按取消处理：不删除。

### 5.2 回退

1. 在现有操作栏点「回退到此」：打开确认。运行中也能点。
2. 取消：什么都不做。
3. 确认时这条已经不能回退（entryId 已不在当前上下文 / 已切会话 / 该条已被移出上下文）：确认无效，并提示。不停止，不删除。
4. 确认成功的顺序：先记住这条用户消息的文字 → 停止正在跑的回合 → 删除这条和它后面的内容 → 把记住的文字放入输入框。
5. 中途失败：停在失败的那一步并提示，并说明已完成的部分（回合是否已停、内容是否已删）。已经停掉的回合不自动继续。已经删掉的内容不写回。
6. 之后按下发送：只发送输入框里的当前文字，不再删除。

### 5.3 重新生成与删除

重新生成：对话已停下，且最后一条用户消息后面已有回复。保留这条原文，删掉它后面的内容，用原文再发一次。不打开编辑框。

删除：当前上下文中的用户消息。先确认。确认后删掉该条及其后内容，不放入输入框。取消则不动。

### 5.4 重新打开

界面历史不得长过截断后的会话，也不得用截断前的显示历史覆盖回来。截断成功即同步写界面历史；写失败按 §3 删除该会话的界面历史文件。

## 6. 架构

四个单元。

1. **消息标识（新增）**：后端 `agent_get_messages` 返回的每条消息带 `entryId`；另给一份「当前上下文 entryId 集合」与「活动分支最后一条用户条目 entryId」。前端在 `src/stores/agent.ts` 新增一次轻量同步（回合结束后按序对齐，只补 `entryId`/`timestamp`，**不重排消息列表**），使刚发出的本地消息也能被指认。实现用 SDK 的 `buildSessionProjection()`（provenance-preserving，`dist/core/session-manager.d.ts:199-200`），不手写会话语义解析。
2. **消息动作**：沿用 `MessageActionBar`。用户消息常驻栏为 `rewind`、`edit`、`copy`；菜单为复制、回退到此、编辑、重新生成、删除。去掉 `exclude`。回退在回合进行中仍可点，编辑、重新生成、删除只在停下时出现。
3. **输入**：编辑框复用底部输入框的文字、图片、拖放（文件 / 文本 / 图片，提示语相同）和 `@`。`/` 只列出技能。不包含模型、模式、审批、联网、生图、朗读、压缩、新会话、增强提示词。按钮只有发送和取消。入口是悬停才出现的铅笔图标。截断成功但发送失败，以及回退确认成功，都要把文字放进底部输入框，需要一条最小接缝（`src/features/chat/input/composerBridge.ts`）：`ChatInput` 挂载时注册 `setValue`。回退确认后的发送、以及编辑失败回填之后的发送，走现有普通发送。编辑输入框里的发送在普通发送之前先完成截断。
4. **会话截断（新增，主进程）**：新 IPC `agent_truncate_to`（snake_case，落 `electron/ipc/register.ts`）。主进程流程：
   1. 取当前 `sessionFile`；若 `isStreaming` 则 `session.abort()`；
   2. `waitForIdle()`（`handle.reload()` 内部同样先等 idle，`workspaceHandle.ts:152`）；
   3. 读文件 → 定位目标 entryId → 校验「其后代集合 == 文件中该行之后的全部行」，不满足则报错返回（对应 §3 的「截断不适用」）；
   4. 删除该条及其后代闭包，写临时文件后 `rename` 覆盖（原子），保留 header 行；
   5. `session.reload()` 让 pi 重读（leaf 自动落到剩下的最后一行，§1 第 9 条）；
   6. 返回剩余消息（含新 entryId 集合），前端据此改写画面与界面历史。

   `WorkspaceHandlePort` 要加 `reload`；如要复用官方解析，可在 `cli/src/pi-sdk.ts` 追加导出 `loadEntriesFromFile` / `buildContextEntries`。

并发口径：同一条会话同一时刻只允许一个截断命令；命令执行期间前端禁用编辑/回退入口。

## 7. 失败与竞态

| 场景 | 行为 |
| --- | --- |
| 截断前会话已被替换（fork / 新建 / 切换） | 命令返回失败，前端提示且不删除、不发送（entryId 已不属于当前会话） |
| 停回合超时或 abort 报错 | 停在「停止」这一步：不截断、不动输入框，提示「停止未完成」 |
| 文件重写失败 | 原文件不被破坏（临时文件 + rename），提示失败；前端保持原画面 |
| 截断成功但界面历史写入失败 | 删除该会话的 ui-history 文件；画面用返回值重建 |
| 截断成功但发送失败 | 不回滚。消息块已移除，文字放入底部输入框，进入不再删除的发送状态 |
| 确认框停留期间该条失效 | 确认时二次校验判据，失效则只提示 |
| 运行中回退与流式事件并发 | 回合已 abort 且 idle 后才改文件；`agent_end`/迟到事件按既有 reducer 规则处理，不回填已删内容 |
| 刷新页面 / 切走工作区 | 后端会话文件已是截断结果，界面历史已同步；不会复活旧内容（§1 第 5 条的对齐规则不再触发） |

## 8. 测试

- 判据：回退在现有悬停操作栏，不悬浮到气泡外。不在当前上下文或助手消息没有回退。回合进行中回退仍可点，编辑不出现。
- 编辑门控：非最后一条用户条目、回合进行中、或不在当前上下文 → 不出现。操作栏不再提供移出上下文，编辑占原位置。
- 编辑交互：点操作栏铅笔后该条消息铺满为简化输入框，可输入文字、放图片、拖入文件/文本/图片；`/` 只有技能，`@` 与底部输入框相同；只有发送和取消。取消后消息块恢复且会话文件不变；发送才截断。
- 状态机（§4）：edit-pending 下确认回退 → 只删一次；rewind-loaded 下发送 → 不触发第二次截断。截断成功但发送失败 → 进入 rewind-loaded，文字在底部输入框。
- 失败回填：截断失败时编辑输入里的文字仍在。发送失败后，底部输入框文字等于取走的那份文字，画面上没有原消息块。
- 回退确认框只有确认和取消，没有「只停止不删除」。
- 主进程命令：timestamp→entryId 语义废弃后的新定位；多分支文件（后代集合 ≠ 后续行）→ 拒绝且文件字节不变；正常会话 → 删除后 `reload` 得到剩余消息；header 行保留。
- 界面历史：截断成功后写盘内容 == 剩余对话；写入失败 → 调用 `ui_history_delete`。
- 回归：`MessageActionBar.test.tsx` 的流式门控用例（`MessageActionBar.test.tsx:80-86`）按新语义改写（回退不再整条隐藏）。
