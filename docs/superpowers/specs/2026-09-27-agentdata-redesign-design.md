# Agent 数据工作台改版

- 日期：2026-09-27
- 状态：待审查
- 范围：`electron-agent/src/features/agentData/` 的六个页面，另有少量渲染层类型和主进程字段补充
- 原型：`.pi/visual/agentdata-prototype.html`（用户已确认，数据为假数据）

## 1. 背景

工作台现在有两行外壳：一行标题区，一行 antd Tabs。每个面板各自堆页头、说明文字、刷新按钮和多条 Alert。同一个面板里常有三四个刷新入口，主次不清。代码索引页的标题、项目路径和统计各占一块。任务页工具栏有五个筛选。

原型把六页统一成一套版式：单行顶栏，页头放标题、计数和主操作，一个面板放工具条和内容，左边列表、右边详情，次要操作收进“更多”菜单，错误集中成页头下的一条横幅。

本稿把原型落到现有代码。原型里有几项现有数据给不出来，第 9 节逐条写明怎么处理。原型没画、但现有代码已有的保护逻辑（版本冲突、离开确认、系统任务只读、诊断只读、操作记录）全部保留。

## 2. 目标与非目标

**目标**

1. 六页使用同一套外壳、页头、横幅、列表-详情布局和更多菜单。
2. 整页刷新只留顶栏一个入口。面板自己的刷新、重新读取和刷新关系按钮去掉，例外见 3.2。
3. Memory 按等级分组浏览，分组上显示数量。
4. 知识页面默认只读，点“编辑”后在原位编辑。
5. 任务行点开详情抽屉，行内操作在悬停或键盘聚焦时出现。
6. 审计诊断默认显示运行诊断，按状态计数，按分类筛选。

**非目标**

- 不改 AgentData RPC 语义、任务调度、Wiki 抽取流程和 CodeGraph 调用方式。
- 不为 Wiki 抽取创建任务。现在的抽取是进程内串行队列，不进任务表（`wikiEngine/service.ts` `ingest()`）。
- 不增加新的统计来源，比如今日新增记忆、跨项目索引过期数、关系数量。
- 不换组件库，继续用 antd v6 和 `antd-style` 的 `createStaticStyles`。
- 不改 Agent 召回范围和记忆归属语义。

## 3. 公共结构

### 3.1 顶栏

`AgentDataCenter` 继续使用 antd `Tabs`，这样现有的 `role="tab"` 断言不受影响。去掉独立的标题区，用 `tabBarExtraContent` 放两侧内容，整个顶栏只有一行，高 48px。

- 左侧：品牌图标和“Agent 数据”。
- 页签：概览、Memory、Wiki、代码索引、任务、审计诊断。每个页签都有图标和文字。
- 任务页签带数量徽标，值是进行中任务数。审计诊断页签带红色徽标，值是需要处理的诊断数。数量为 0 或未获取时不显示徽标。
- 右侧：Runtime 状态点和文字，保留 `data-testid="agent-data-runtime"` 与 `data-state`；然后是刷新按钮，可访问名称仍是“刷新 Agent 数据”。
- 面板宽度小于 760px 时，页签文字改为视觉隐藏，只显示图标。文字仍保留在可访问树中，页签名称不变。品牌文字直接隐藏。

徽标数据：

- 进行中：`AgentDataTaskProvider` 已从 `tasks.list` 拿到 `activeCount`，但只存在 ref 里。改为通过 monitor 暴露 `activeCount`。它是服务端计数，包含用户任务和系统任务，所以徽标的 `title` 写“进行中任务（含后台）”。
- 需处理：`WorkbenchOverview.diagnostics.actionRequired`。只有本次运行做过诊断检查才有这个值，否则不显示徽标。

运行时出错时，顶栏下方显示一条错误横幅，也就是现在的“运行时：…”。

### 3.2 统一刷新

`AgentDataCenter` 新增 `refreshToken` 计数器。点顶栏刷新按钮后，计数器加一，同时执行现在的 `refreshResources()` 和 `monitor.refresh()`。每个面板都接收 `refreshToken`，并把它加进读取数据的 effect 依赖里，和现在的 `watchedTaskVersion` 并列。

下列面板内刷新按钮删除：“刷新 Memory”“刷新知识库”“刷新当前知识库”“刷新代码工作区”“重新读取源码”“刷新关系”“刷新记录”。

有两处例外。读取详情失败时，详情区里保留“重试”按钮，只作用于这一条详情。代码索引页的“更多”菜单保留“刷新状态”，只重新读取当前项目的索引状态。

### 3.3 共用组件

新建 `workbench/` 目录，放以下组件：

| 组件 | 职责 |
| --- | --- |
| `PageHeader` | 标题、副标题或计数、右侧操作。高度至少 40px，窄屏换行。 |
| `PageBanner` | 页头下的横幅，类型为 error、warning、info，右侧可放一两个按钮。同一页多个错误合成一条，每个来源一行，前面写来源名。 |
| `SplitPane` | 左列 280px，右列自适应。容器宽度小于 800px 时变成单栏，`data-detail` 决定显示哪一栏，详情头显示返回按钮。沿用 `memoryStyles.layout` 现在的容器查询写法。 |
| `MoreMenu` | antd `Dropdown`，触发按钮是“⋯”图标，必须有 `aria-label`。危险项标红，并排在分隔线后。 |
| `StatusTag` | 各页状态到 antd Tag 颜色的映射，集中在一个文件里。 |

版式数值：页面最大宽度 1180px，内边距 16px/24px，窄屏 12px；面板圆角 10px，1px `colorBorderSecondary` 边框；面板工具条最小高度 46px。颜色只使用 `cssVar` token，浅色和深色都要验收。

提示方式：成功提示写在页头下的一行 `role="status"` 文字里，下一次操作时清掉。不使用 toast，现有“记忆已保存。”这类断言可以保留。

按钮的可见文字必须包含在可访问名称里。所有两个汉字的纯文字按钮继续设置 `autoInsertSpace={false}`。

## 4. 概览

页头：标题“概览”，副标题“全部项目”，右侧是“新增记忆”和主按钮“新建知识库”。两个按钮继续走现有的 `ResourceNavigation` 的 `mode: 'create'`。

`diagnostics.actionRequired > 0` 时，页头下显示错误横幅“有 N 项诊断需要处理”和“查看”按钮，点击跳到审计诊断。

KPI 条是一行四格，1px 分隔。每格可点击，并进入对应页面。

| 格 | 主值 | 副行 | 数据 |
| --- | --- | --- | --- |
| 记忆 | `memory.total` 条记忆 | `L0 x · L1 x · L2 x · L3 x` | `MemoryOverview` |
| 知识页面 | `libraries.pages` 个知识页面 | `libraries.total` 个知识库 | `WorkbenchOverview.libraries` |
| 代码索引 | `x / y` 个项目已索引 | “按已知项目统计” | `code.projects()` |
| 任务 | `activeTasks` 个进行中 | 有失败时显示红字“N 个失败” | `WorkbenchOverview` |

某个值读取失败时，这一格显示“未获取”，副行写原因，不用 0 顶替。现有的 Metric 和 Stat 两排卡片合并成这一条。

下方三列用 auto-fit，每列最小 320px：

- 最近任务：取 `monitor.tasks` 前 4 条。每行显示名称，下面一行是阶段、错误或相对时间，右侧是状态标签。点击打开该任务的详情抽屉。
- 知识库：从 `wiki.list()` 取最近更新的 4 个库，每行显示名称、状态和页数，点击进入该库。原型这里写的是“最近知识页面”。但 `WorkbenchOverview.recentPages` 在 `runtime.ts` `workbenchOverview()` 中从来没有填充，页面也没有更新时间，所以改成列出知识库。
- 最近记忆：`recentMemories` 前 3 条。正文最多两行，元信息是等级、归属、相对时间。点击打开该记忆。

相对时间使用 `SubAgentCard.tsx` 里现有的 `formatRelative`。把它移到 `src/lib/`，两边共用。

## 5. Memory

页头：标题“Memory”，副标题“N 条记忆”，其中 N 为 `overview.total`，右侧是主按钮“新增记忆”。

分组：页头下是一组 `Radio.Group` 按钮，按钮依次是 L0、L1、L2、L3，隔开一段后是“对话记录”。没有“全部”。等级按钮上的数量来自 `MemoryOverview.byLevel`，这是全部项目的总数，不跟随归属筛选。按钮的 `title` 写明这一点。“对话记录”不显示数量，因为没有计数接口。

- 默认分组是 L2，与原型一致。
- 分组切换直接用 `MemoryListInput.level` 做服务端过滤，现有接口已经支持。对话记录切到 `kind: 'conversation'`。
- 删除原来的“记忆 / 对话记录”Tabs 和“记忆层级”下拉。

面板工具条：左侧是当前分组的说明，例如“L2 · 场景摘要”或“对话记录只读”。说明文字来自 `memoryLevelLabels`：L0 历史记录、L1 事实与偏好、L2 场景摘要、L3 长期画像。右侧是搜索框“搜索内容”和归属筛选，选项是全部项目、全局和各真实项目。选中的项目失效时，仍显示“所选项目已不可用”。

列表：每行显示最多两行摘要，下面一行是归属和相对时间。“继续加载”留在列表底部。

详情头：左侧是等级标签、归属、更新时间和“版本 rN · 人工/自动”，右侧是“编辑”和更多菜单。菜单项是“打开来源会话”，然后是分隔线和“删除记忆”。来源会话无法打开时，这一项置灰，并显示原因：“未记录来源”“会话已移除”或“来源状态未获取”。编辑按钮的可访问名称保持“编辑记忆”。对话记录没有编辑按钮和更多菜单，显示“只读”。

详情正文、结构化 JSON、原始 JSON 折叠区和来源一节保持现有 `MemoryDetail` 的逻辑。

编辑：仍在右侧详情区原位进行，沿用 `MemoryEditor`，包括 revision 冲突、后台更新提示、外部删除后保留草稿、`Ctrl+S`、`Escape` 走离开确认。按钮行把“关闭编辑”和主按钮“保存记忆”移到详情头右侧，文字不变，这样可见文字和可访问名称一致。L0 记录的等级锁定。保存后，如果等级变了，分组切到新等级并选中这条，提示“已保存，已移到 Lx”。

新增：点“新增记忆”打开 Modal，里面嵌入同一个 `MemoryEditor`，不另写表单。`MemoryEditor` 增加 `initialLevel` 属性，只在没有 `record` 时生效。现在新建草稿固定为 L1。等级只能选 L1–L3。当前分组是 L1–L3 时，默认选当前分组，否则默认 L2。归属必须选，来源说明可选。关闭 Modal 前也走 `confirmLeave`。保存后关闭 Modal，切到该等级并选中新记录。

从概览或审计跳转带来记忆 `id` 时，先读取详情，再按返回的 `level` 切换分组。原来的“清空筛选并选中”逻辑不变。

## 6. Wiki

### 6.1 知识库列表

页头：标题“知识库”，副标题“N 个”，右侧是搜索框“搜索名称或用途”和主按钮“新建知识库”。删除排序下拉，列表固定按 `updatedAt` 倒序。

卡片网格按 auto-fill 排列，每张最小 260px。卡片内容：

- 第一行：名称。
- 第二行：用途，没有时显示“未填写用途”。
- 底行：状态标签，然后是“N 页 · M 份资料”。
- `failed` 时再加一行红字，显示 `syncError`。

卡片右上角是更多菜单：“属性”“打开存储位置”，分隔线后是“删除知识库”。删除仍要输入名称确认。菜单项的可访问名称保持“删除知识库 {名称}”。

资料数需要主进程补一个字段，见第 9 节。

### 6.2 知识库工作区

页头：

- 面包屑“知识库 / {名称}”。“知识库”是返回链接，可访问名称为“返回知识库列表”。
- 状态标签和“N 份资料 · M 页”。
- 主按钮“开始抽取”。没有原文、库处于 processing 或只读时禁用。processing 时按钮文字为“抽取中…”。
- 更多菜单：“编辑属性”“打开存储位置”“重置为草稿”，分隔线后是“删除知识库”。“重置为草稿”只在 pending 或 processing 时可用。

删除现有的刷新按钮、属性抽屉，以及独立的“重置状态”按钮。

横幅：

- processing：信息横幅“正在抽取，完成前内容只读 · {阶段}”。阶段由 `internalStatus` 映射：`scanning` 为“扫描原文”，`ingesting` 为“抽取页面”，`rebuilding-index` 为“重建索引”，其他值原样显示。不放“查看任务”，因为抽取没有任务记录。
- failed：错误横幅显示 `syncError`，“开始抽取”可以重新点击。
- 读取错误：合并成一条错误横幅。

抽取完成的感知：`wiki.ingest` 会等到本次抽取结束才返回，发起者返回后刷新一次，和现在一样。打开工作区时库已经在 processing，这种情况在工作区可见时每 2 秒 `wiki.read` 一次。状态离开 processing 后停止轮询，并重新读取列表。工作区隐藏时暂停。

面板：顶部是分段控件，选项为原始资料 (N)、知识页面 (N)、抽取模板、检索。资料和页面两个分段在右侧显示筛选框。“上传原文”按钮只在原始资料分段出现，processing 时禁用。

- 原始资料：左侧列表显示文件名和状态（已上传、已抽取、抽取失败）。右侧显示正文预览，详情头有“删除资料”。删除前要确认，这是新增的确认。
- 知识页面：左侧列表显示标题和类型。右侧默认只读，渲染 Markdown。详情头有“编辑”和更多菜单，菜单项是“删除页面”，删除前要确认。点“编辑”后原位切到 `WikiPageEditor`，字段是标题和正文，按钮是“取消”和“保存”。有未保存修改时，离开、切换页面或返回都走现有的放弃确认。库不是 ready 时页面列表为空，空态写“抽取完成后显示知识页面”。
- 抽取模板：`purpose.md` 和 `schema.md` 并排显示，每个至少 300px，窄屏上下排列。每个编辑器上方有文件名、一句说明和各自的保存按钮。
- 检索：输入框，回车或点“检索”执行。下方是结果列表，点结果跳到对应页面。空态显示“图谱共 N 条边”。分段名从“检索与图谱”改成“检索”。

## 7. 代码索引

页头从左到右：

1. 标题“代码索引”。
2. 项目下拉。选项只显示项目名，完整路径放在选项的第二行和 `title` 里。
3. 状态标签。
4. 统计：文件、节点、边、同步于 `lastIndexedAt`。没有的数值显示“未提供”。
5. 主按钮：已索引时是“同步索引”，未索引时是“建立索引”。
6. 更多菜单：“刷新状态”“打开项目目录”。

没有选择项目时，只显示页头和空态“请选择一个项目”。

删除“Code Retrieval”标题、路径说明段、统计卡片、“刷新代码工作区”，以及连续堆叠的多条 Alert。

状态映射，依据 `codeGraphEngine.ts` 的 `state`：

| state | 标签 | 横幅 | 查询 | 主按钮 |
| --- | --- | --- | --- | --- |
| 检查中或未获取 | 检查中 | 无 | 禁用 | 禁用 |
| `indexed` | 已索引 | 无 | 可用 | 同步索引 |
| `stale` | 索引过期 | 警告：“索引已过期，结果可能不准”＋“同步” | 可用 | 同步索引 |
| `partial` | 索引不完整 | 警告：“上次索引未完成，下次同步会全量重建”＋“同步” | 可用 | 同步索引 |
| `failed` | 索引失败 | 错误：`message`＋“同步” | 可用 | 同步索引 |
| `indexing` | 索引中 | 信息：“正在更新索引” | 禁用 | 禁用 |
| `unavailable` 或 `indexed: false` | 未索引 | 无；内容区空态“这个项目还没有索引”＋“建立索引” | 禁用 | 建立索引 |
| `sdk_unavailable` 或 `sdkAvailable === false` | SDK 不可用 | 错误：“内置 CodeGraph SDK 不可用，请检查安装包”＋`message` | 禁用 | 禁用 |
| 读取状态报错 | 未获取 | 错误：原因；有上次结果时注明“保留上次状态” | 按上次状态 | 禁用 |

映射写成纯函数 `codeIndexPresentation(status, error)`，单独测试。

建立或同步索引后，页头下显示信息横幅“已加入任务 · {状态} · {进度}”和“查看任务”按钮，内容和现在的 `createdTask` 卡片相同。

面板工具条只有一行：左侧是搜索框，右侧是分段“符号 / 相关上下文”。搜索框为空时浏览文件，placeholder 写“搜索符号或文件名；留空浏览文件”。“相关上下文”在搜索框为空时禁用。

列表-详情：

- 左侧：“N 个结果”，每行显示符号名、kind 标签，以及文件末两段加行号。
- 右侧详情头：符号名、kind、“复制相对路径”“打开文件”。“打开文件”的可访问名称保持“使用系统打开文件”，它包含可见文字。下面一行是 `file:line`。
- 源码预览沿用 `CodeSourceDetail`：整文件滚动到目标行，目标行高亮，缺行号或越界时明确提示。
- “符号上下文”折叠区保留。
- 关系用分段“调用者 / 被调用者 / 影响”，沿用 `CodeRelations`。原型里分段按钮带数量，现在去掉，因为要调用三次工具才能拿到。
- 未识别的返回结果仍展示原文，“原始结果”折叠区保留。

各项目独立保存搜索词、项目被移除后撤销旧查询、同名符号用节点 ID 消歧，这些逻辑都不变。

## 8. 任务与审计诊断

### 8.1 任务

页头：标题“任务”，副标题“N 个进行中”，右侧是“清理已结束 (N)”。N 是当前筛选下可删除的用户任务数，清理仍要确认。

工具条：

- 分段“进行中 / 历史 / 全部”，带数量，数量按已加载的用户任务计算。默认“进行中”。
- 搜索“搜索任务、资源或工作区”。
- 类型下拉。
- 工作区下拉。
- 工具条下方保留一行说明：“筛选与清理仅作用于已加载的用户任务；系统后台任务只读。”

删除“任务状态”下拉，状态区分改由分段承担，失败任务在“历史”里显示红色标签。请审查时确认这项删除。

### 8.2 审计诊断

页头：标题“审计诊断”，右侧是分段“运行诊断 / 操作记录”。默认“运行诊断”。从资源跳转进来时，也就是带 `resource`，切到“操作记录”并带上筛选。这一页保留操作记录，原型没有画。

运行诊断：

- 副标题：“检查于 {时间} · 只读取状态，不会自动修复”。右侧是“重新检查”。
- 三格计数：需要处理（`action_required`，红）、未检查（`unchecked`，灰）、正常（`ok`，绿）。原型写的是“注意”，后端没有这一级，这里改为“未检查”。
- 分类分段：“全部”加上当前结果里实际出现的分类，分类有代码索引、知识库、记忆、运行服务。只有一个分类时不显示分段。现在的诊断只产生代码索引项。
- 删除“诊断资源”下拉。请审查时确认这项删除。
- 列表按“需要处理、未检查、正常”排序。每行显示状态点、消息（经 `redact`），下方是分类和资源名，项目只显示目录名。右侧是动作按钮：
  - “前往 →”：有 `resource` 时显示，走 `resourceNavigation`。
  - “打开问题文件”：`action === 'open_file'` 时显示。
  - “配置说明”：`action === 'configure_codegraph'` 时显示，可访问名称保持“查看配置说明”。点击打开 Modal，文案沿用现有说明，按钮是“前往代码索引”。这个名称原来是“前往代码配置”，测试要跟着改。
