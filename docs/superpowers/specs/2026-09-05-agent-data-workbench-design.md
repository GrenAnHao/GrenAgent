# Agent 数据工作台：六面板详细设计

日期：2026-09-05

状态：用户已确认本详细设计，进入实施计划拆分；尚未进入生产代码实现。

## 1. 已确认的方向

- 保留六个面板：概览、Memory、Wiki、代码索引、任务、审计诊断。
- 延续 GrenAgent 的桌面外壳和 Ant Design / Lobe 主题，不引入另一套组件库。
- Wiki 是独立命名的知识库，一个库可关联多个项目，一个项目也可关联多个库。
- Markdown 文件继续保存 Wiki 正文；AgentData 管理资料、索引、项目关联和任务。
- 任务清理保留已经实现的终态保护、确认和筛选范围语义。

本稿中的新接口、字段和交互都是设计要求，不表示当前版本已经提供。

## 2. 当前界面的主要缺口

当前 Memory / Wiki 进入后要求先搜索，没有默认浏览列表；完整内容缺少详情入口。Wiki 已有文件读写 RPC，但渲染层尚未接入列表、正文、索引重建，也没有具名知识库或资料管理。

当前总刷新通过 loading 状态卸载子面板，容易丢失筛选和浏览位置。新建同步任务后直接切到任务页，列表又不一定立即刷新。项目路径占用大量宽度，UUID 临时工作区难以辨认。

代码索引面板只使用搜索接口，没有呈现后端已有的调用关系能力。审计把原始 JSON 放在表格中，用户难以判断发生了什么、应该处理什么。

## 3. 信息架构与公共布局

### 3.1 导航

```text
Agent 数据                                  运行状态 · 进行中任务入口
概览   Memory   Wiki   代码索引   任务   审计诊断
─────────────────────────────────────────────────────────────
当前面板标题 / 面包屑                         当前页面的主要操作
搜索与本地筛选
内容区
```

全局页头不放强制项目选择器。项目范围属于各面板自己的筛选或上下文：

| 面板 | 默认范围 | 项目切换规则 |
| --- | --- | --- |
| 概览 | 全部本地数据 | 不跟随聊天项目 |
| Memory | 全部项目与全局记忆 | 面板内筛选；Agent 自动召回仍遵守原项目范围 |
| Wiki | 全部知识库 | 可按关联项目筛选；进入某库后固定库 ID |
| 代码索引 | 明确选定一个项目 | 初次可预选当前真实项目；不跨库合并符号 |
| 任务 | 用户任务，全部项目 | 本地筛选；后台系统任务单独分组 |
| 审计诊断 | 全部本地事件 | 可按资源、项目、时间缩小范围 |

### 3.2 状态保留与更新

- 六个面板分别记住关键词、筛选、选中条目、页码和滚动位置；关闭应用后不要求恢复全部临时编辑状态。
- 切标签或后台刷新不卸载正在浏览的内容。初次加载使用骨架，后续刷新保留已有结果并显示小型刷新状态。
- 任务创建成功后留在原页显示“已加入任务”；“查看任务”可打开指定任务详情。
- 可见任务列表、资源页或详情订阅了活动任务时，共用一个每 2 秒刷新的任务状态来源；仅历史任务时停止自动轮询。终态到达后刷新关联资源，不要求用户进入任务页。窗口失焦暂停，重新聚焦刷新一次。后续若已有统一事件通知，可替代轮询，不同时维护两套状态来源。
- 数据失败、真实空集和筛选无结果必须分别显示。读取失败不能把上一次非空结果替换成“暂无数据”。

### 3.3 视觉尺度

主验收窗口为 1200×800 与 1440×900；布局断点按面板可用宽度计算。

| 元素 | 设计值 |
| --- | --- |
| 模块页头 / 标签导航 | 56px / 44px |
| 页面内边距 | 20–24px；窄窗口 16px |
| 页面标题 / 分组标题 / 正文 | 18px / 14px / 13–14px |
| 辅助信息 | 12px，不用于承载主要操作或错误原因 |
| 输入框与普通按钮 | 高 32px；主对话框操作 36px |
| 表格普通行 | 最小 40px，长摘要可增高 |
| 间距 / 圆角 | 8、12、16、24px / 沿用 6–8px |
| 详情抽屉 | 默认 400px，受窗口宽度约束 |
| 文档正文 | 行宽上限 760px，行高约 1.65 |

颜色使用现有 `colorBgLayout`、`colorBgContainer`、`colorBgElevated`、`colorText`、`colorBorderSecondary` 和语义状态 token。浅色和深色均需验收，正文对比度不低于 4.5:1。操作不能只靠红绿颜色区分。

表格使用可用宽度，文档限制正文行宽。路径默认显示项目名和相对路径；详情提供完整路径、复制和打开位置。临时会话工作区显示“临时会话”及可用标题，不直接把 UUID 当项目名称。

所有图标操作提供名称。详情关闭返回原选中条目，键盘焦点返回触发按钮；编辑时 Ctrl+S 保存，Escape 不直接丢弃未保存内容。

## 4. 概览面板

**目的：** 告诉用户已有何种数据，以及现在需要处理什么。

```text
数据概览
记忆条数        知识库 / 页面        已建索引项目        进行中任务

需要处理                                      最近更新
资料有变更，等待抽取     打开知识库              产品概述 · Wiki
索引同步失败            查看原因                使用偏好 · Memory

快速入口：新建知识库 · 录入记忆 · 选择代码项目
```

- 摘要数字可点击进入带对应筛选的面板。没有可计算数据时显示“未获取”，不补零。
- “需要处理”只列真实失败、待抽取资料、索引过期或文件诊断问题；没有问题则简短显示“无需处理”。
- 最近更新显示名称、类型、来源和更新时间，点击直接打开内容，不跳入无选中状态的列表。
- 全空状态说明资料从哪里来，保留“新建知识库”和“开始一次对话”两个入口，不用一排零值卡片占满首屏。
- 不展示虚构健康分、召回命中率或 Token 节省量；这些当前没有可靠统计来源。

## 5. Memory 面板

**布局：** 可浏览的记忆列表 + 右侧详情。默认展示最近更新，关键词为空也有结果。

```text
Memory                                            新增记忆
搜索记忆       全部项目       类型       最近更新
──────────────────────────────────────────────────────────
条目列表                              详情
事实与偏好 · 喜欢深色主题               内容 / 结构化字段
项目 A · 来源对话                      类型：事实与偏好 · L1
                                      归属：项目 A
场景摘要 · 发布流程                     来源：打开会话
全局 · 更新于……                        编辑   删除
```

### 5.1 分类与默认数据

- 顶部提供“记忆 / 对话记录”切换。对话记录来自捕获存储，不假装它们已成为 `memories` 表中的 L0 记录。
- 记忆类型使用“事实与偏好”“场景摘要”“长期画像”；详情保留 L1/L2/L3 技术标识。
- 内容列表显示最多两行摘要。L1 的 JSON 展示为可读字段，原始 JSON 放在详情折叠区。
- 项目记忆标明来源项目，全局记忆标明“全局”。全局管理页可浏览全部本地记录，不扩大 Agent 自动召回范围。
- 每页 50 条，以服务端游标分页；关键词筛选采用 300ms 防抖并丢弃过期响应。

### 5.2 新增与编辑

- “新增记忆”抽屉填写内容、归属和可选来源；默认新增“事实与偏好”。项目归属必须选择一个真实项目，不能默认写入当前临时会话目录。
- 编辑不默默改变归属；改变项目/全局归属是独立字段，并提示影响哪些 Agent 的召回范围。
- 人工编辑标记为人工版本；后台提炼不得覆盖该记录。新提炼事实可形成独立条目，本版不设计自动语义合并。
- 保存按记录 revision 或 content hash 检查并发修改。冲突时保留用户输入，提供重新载入原版本的入口。
- 对话原文只读，显示来源、时间和命中上下文。来源会话已不存在时显示“会话已移除”，仍可读已捕获片段。
- 删除当前记忆需确认；不删除来源对话。进入删除成功状态后同步更新列表与统计。

**需新增能力：** 无关键词列表、分页、按 ID 更新、人工来源标记及并发版本校验。不能只给现有搜索结果增加一个编辑按钮。

## 6. Wiki 面板

### 6.1 知识库列表

```text
Wiki                                             新建知识库
搜索名称或用途                全部关联项目       最近更新
──────────────────────────────────────────────────────────
知识库             关联项目       资料 / 页面       状态
产品知识库         项目 A、B      6 / 12            可用 · 2 份待更新
排障手册           未关联         0 / 0             草稿
```

名称与用途是第一层信息；库 ID、完整目录路径放入详情。点击整行进入库内，行尾菜单提供重命名、管理关联项目、打开存储位置、删除知识库。

库的“可用”与处理进度分开：已有页面的库在抽取新资料时仍可用。状态展示规则：

| 条件 | 展示 |
| --- | --- |
| 没有资料与页面 | 草稿 |
| 有资料但尚无生成页面 | 待抽取 |
| 存在可读页面 | 可用 |
| 有未处理的资料版本 | 附加“有资料待更新” |
| 抽取正在进行 | 显示当前任务阶段及查看任务入口 |
| 最近抽取失败 | 显示失败提示；已有可用页面仍可读取 |

### 6.2 新建知识库

宽约 520px 的对话框：

- 名称：必填，去除首尾空格，1–80 字符。
- 用途说明：可选，最多 500 字符，帮助用户区分资料库。
- 关联项目：可选多选，默认不自动关联全部项目。
- 操作：“取消”“创建知识库”。

创建仅保存库元数据和目录，状态为草稿，不触发模型、导入或项目扫描。成功后进入新库的空状态，主操作为“添加资料”，次操作为“新建页面”。

知识库 ID 稳定，允许不同库显示相同名称。重命名不改变 ID、文件位置或项目关联。

### 6.3 库内布局

```text
‹ 全部知识库   产品知识库                添加资料   开始抽取   更多
关联：项目 A、项目 B                     待处理资料：2
─────────────────────────────────────────────────────────────
资料 / 知识页面           内容                         属性
搜索当前列表             预览 / 编辑                   来源及版本
                         页面标题                     关联项目
产品说明.md              Markdown 正文                更新时间
操作手册.md                                           人工锁定
                                                      文件位置
─────────────────────────────────────────────────────────────
任务：正在处理操作手册.md                              查看任务
```

- 面板可用宽度 ≥1160px：左栏 240px，正文最小 560px，属性栏 264px；剩余空间给正文。
- 800–1159px：左栏 224px + 正文，属性改为抽屉。
- <800px：列表与详情逐级导航，保留返回位置，不压缩成三列小字。
- “资料”和“知识页面”是同一左栏中的切换，不同时堆两棵长树。
- 资料列表展示文件名、来源和处理状态；页面列表展示标题、人工锁定与来源异常标记。

### 6.4 添加资料

对话框含“上传文件 / 手动录入 / 从项目导入”三个页签。

| 入口 | 字段与行为 |
| --- | --- |
| 上传文件 | 本版支持 Markdown、TXT；多文件逐项显示成功或失败，不声称支持尚未实现的二进制文档解析 |
| 手动录入 | 文件名 + Markdown 编辑区 + 预览；保存到该库的原始资料集合 |
| 从项目导入 | 显式选择已关联项目及资料路径；展示将导入的文件后确认；只读取源项目，保存库内快照 |

保存资料与抽取分开。保存完成后提示“资料已添加”，提供“开始抽取”和“稍后处理”。知识库关联项目不等于导入项目资料。

每份资料拥有独立稳定 ID；名称、来源项目和相对路径是来源属性，不充当 ID。两个项目的 `README.md` 可以同时存在，列表必须显示来源项目。上传或手动录入同名内容时，默认作为新资料；只有用户显式选择“更新这份资料”才追加既有 ID 的 revision。

更新原文产生新 source revision，保留知识页面当前引用的旧快照。导入资料不写回或删除项目中的原文件。

### 6.5 抽取与索引重建

- 默认只抽取新增、内容变化和上次失败的资料；比较内容 hash，未变化的成功资料跳过。
- 启动前展示目标资料数量、所用模型及“会调用模型”的说明；不编造费用估算。
- 抽取过程中显示阶段与已处理数量。无法测量的阶段使用不定进度，不以虚假百分比表示。
- 生成结果带来源 ID 与版本。发布前再次检查页面 revision 和 locked；期间的人工修改优先，生成结果不得直接覆盖。
- 页面可关联 0..N 个 `{sourceId, revision}` 引用。本版自动抽取默认生成每份资料的独立页面；用户维护的多来源页面不在单份资料的增量抽取中被覆盖。任何更新不得抹掉其它来源引用，本版不自动合并多来源正文。
- 锁定页记为“跳过：人工锁定”，其余资料继续处理；结果汇总成功、跳过和失败数量。
- 取消为协作式停止，UI 在执行器确认前显示“正在取消”；停止后保留已成功发布的页面。
- “重建索引”放在更多菜单，说明“不调用模型，不改正文”，展示扫描诊断并提供问题文件入口。

### 6.6 人工新建与编辑页面

- “新建页面”直接创建知识页面，不经过资料抽取。填写标题和 Markdown 正文，可选关联已有资料。
- “编辑页面”显示正文编辑器、预览和未保存标记。应用内人工保存默认 `locked=true`，并解释“后续抽取不会覆盖”。
- 用户仍可继续编辑锁定页面；“允许自动更新”需显式解除锁定。无来源的人工页面不提供可执行的自动更新操作，提示先关联原始资料；多来源页面按显式维护流程处理。
- 手工页面没有资料来源时显示“人工创建”，不能伪造来源文件。
- 外部编辑文件不自动视为已锁定。读取时识别 frontmatter；未声明 locked 的页面仍按未锁定处理，界面明确提示。
- 外部文件变化通过 hash 检查触发冲突提示，用户草稿不丢弃。页面保存后同步更新索引；只读模式不出现可执行写入入口。

### 6.7 关联范围与删除

项目关联只改变使用范围，既不复制 Markdown，也不触发扫描或抽取。项目 Agent 的检索、列表和读取仅限显式关联知识库；零关联返回空集，不能用省略 scope 来变成全库访问。全局管理页可浏览未关联库。

| 操作 | 影响及保护 |
| --- | --- |
| 解除项目关联 | 不删除库、页面和资料；该项目后续不能经项目范围读取该库 |
| 删除原始资料 | 先展示受影响页面；移除后续抽取来源，不删除项目源文件；保留引用页面和必要快照，标记“来源已删除” |
| 删除知识页面 | 保留原始资料；不由后台悄悄重新生成，重新生成必须显式触发 |
| 删除知识库 | 确认库名、资料/页面数量和关联项目；删除库文件、索引、关联，保留审计及任务历史，不删除项目目录 |

相关写入任务未停止时禁止删除资源：支持取消的任务提供“取消任务并等待停止”，不可取消的系统任务显示“等待任务结束”，不能提供虚假取消入口。服务端进入资源删除流程后阻止新写入任务入队，并拒绝旧任务结果发布，避免检查结束后又被重新写入。确认中的目标使用稳定 ID 快照；重命名或刷新不能让删除目标漂移。

## 7. 代码索引面板

```text
代码索引
项目列表                   搜索文件或符号                 同步索引
─────────────────────────────────────────────────────────────
项目 A · 已索引             命中结果 / 源码                关系
项目 B · 未索引             文件、符号、行号               调用者
                           源码正文                      被调用者
                           当前选中符号                  影响范围
```

- 左侧只列真实项目，默认不混入临时会话工作目录；可显示项目根路径帮助区分同名项目。
- 未选项目时说明“请选择一个代码项目”。未建索引时给出“建立索引”入口；已有索引使用“同步索引”。
- 文件、符号与关系查看复用现有七种只读 CodeGraph 查询。缺字段显示“未提供”，不把未知统计显示成 0。
- 源码详情提供打开文件、复制相对路径、跳转指定行；调用关系默认列表，图形关系作为有数据时的可选视图，不画空关系图。
- 切换项目清理上一项目的结果和在途响应，保留各项目自己的搜索词。
- 查询不隐式建立索引。CLI 缺失、索引缺失、连接失败分别说明；失败不让用户反复点一个无反馈的同步按钮。
- 索引任务完成后更新项目状态和当前查询，不强制离开正在阅读的源码。

## 8. 任务面板

### 8.1 布局与分类

```text
任务                                      清理已结束
进行中 / 历史        搜索       类型       项目
─────────────────────────────────────────────────────
任务名称          来源          状态          时间
同步代码索引      项目 A        正在构建      10:20
抽取知识资料      产品知识库    等待中        10:21

后台系统任务 · 折叠显示
```

用户任务默认可见，后台记忆提炼等任务作为单独分组。行键使用“任务来源＋ID”，防止 `agent_jobs` 与 `service_tasks` 的 ID 或语义混用。

技术名称映射为中文，例如 `codegraph.sync` 为“同步代码索引”、`memory_extract` 为“提炼记忆”。原始 kind 和 ID 保留在详情。

详情抽屉展示资源、来源项目、状态、创建/更新时间、错误和可用结果。阶段日志仅显示真实采集到的事件，没有日志时不生成模拟时间线。

### 8.2 操作矩阵

| 任务类别 | 等待 / 运行 | 已完成 | 失败 / 已取消 |
| --- | --- | --- | --- |
| 用户同步/抽取任务 | 支持时取消；运行中取消先显示请求中 | 查看关联资源、删除记录 | 查看原因、支持时重新执行、删除记录 |
| 后台系统任务 | 本版先只读详情，按实际能力显示是否可取消 | 只读详情 | 只读详情与重试次数 |

后端返回能力决定操作，前端不能把系统任务按钮路由到 `admin.jobs.*`。

“重新执行”创建关联旧任务的新记录，不篡改原任务终态；目标已删除或同一资源正在执行时禁止重复创建。批量清理只处理当前筛选内的可删除终态记录，确认框显示数量，保留现有审计和产物。

## 9. 审计诊断面板

面板内分为“操作记录”和“运行诊断”。

### 操作记录

默认按时间倒序，显示“在产品知识库保存了页面《产品概述》”一类可读描述。详情才展示事件 ID、资源 ID、字段变化和脱敏 JSON。

提供动作类型、资源和时间筛选；服务端分页。复制或导出使用同一脱敏规则，不能只在页面上遮蔽密钥。资源已删除仍保留可读摘要，不依赖实时查到原资源才能显示历史。

### 运行诊断

按具体问题组织：运行时连接、扩展是否加载、Wiki 文件/索引一致性、CodeGraph CLI/索引状态。每项显示“正常 / 需要处理 / 未检查”、最近检查时间、错误原因与可用操作。

例：Wiki 文件修改但索引未更新，给出“重建索引”；元数据损坏，给出“打开问题文件”；CodeGraph CLI 缺失，给出配置说明，不自动下载或安装。

诊断动作只读；需要写入的修复入口独立确认。不得把“当前查询无返回”当作系统健康结论。

## 10. 后端能力与领域模型

### 10.1 Wiki 的新对象

| 对象 | 必要信息 |
| --- | --- |
| 知识库 | 稳定 ID、名称、用途、创建/更新时间、存储位置 |
| 项目关联 | 知识库 ID、规范化项目路径/ID |
| 原始资料 | 稳定来源 ID、所属库、来源类型、来源项目及相对路径、版本、内容 hash、处理状态 |
| 知识页面 | 所属库、页面 ID、标题、正文文件、0..N 个来源 ID/版本引用、locked、内容 hash/revision、更新时间 |
| 处理任务关联 | 任务来源与 ID、目标库/资料/页面、重试来源、可执行操作 |

不引入 Team、多用户 ACL、云同步、公开市场或向量检索。本地项目范围检查仍由服务端执行，不能仅依靠界面筛选。

### 10.2 兼容旧数据

- 持久化“旧 workspace → 知识库 ID”映射，一对一登记原有桶，名称默认使用项目名并允许用户重命名。
- 初次登记只保留原项目关联，不默认加入其它项目。重跑不得创建重复库、复制原文或覆盖手工页面。
- 初期允许知识库存储位置指向原 bucket，保留页面 ID、locked、来源快照与迁移标记；不为展示名称而搬动目录。
- 旧 workspace 写入接口只解析其原映射库；映射只用于定位，不授予访问权，兼容请求仍检查当前项目关联，解绑后同样拒绝。新接口使用知识库 ID，一个项目关联多个库时，写入必须指定目标库，不能猜测。
- 新版 Agent 可在项目关联库内检索；兼容旧版调用不在升级时自动扩大到所有新关联库。

### 10.3 能力增量

| 可复用 | 需要新增或扩展 |
| --- | --- |
| Wiki Markdown 读取、列表、原文快照、索引重建 | 具名库与关联、资料生命周期、人工页面写入、版本冲突 |
| Memory 搜索、捕获、删除与分层作用域 | 默认列表/分页、人工新增/更新、人工版本保护 |
| CodeGraph 七种只读 RPC | renderer IPC 与结构化详情组件 |
| 用户任务创建、取消、终态清理 | 聚合只读系统任务、重试关联、可用能力、真实阶段记录 |
| 审计事件与基础诊断 | 分页/筛选、资源摘要、文件索引诊断聚合 |

## 11. 交互状态与验收

以下为必须覆盖的设计验收项：

1. 切换聊天项目和数据标签后，原数据页面的筛选、选中项、滚动位置保持。
2. 初次空库能创建知识库、录入资料；没有资料时不出现可执行的抽取按钮。
3. 同一库关联两个项目只保留一份正文；解绑后项目范围读取被后端拒绝或返回无可用库。
4. 两项目同名 `README.md` 不互相覆盖，用户可辨认来源。
5. 用户保存页面默认锁定；抽取遇锁定页跳过，期间人工编辑不被旧生成结果覆盖。
6. 资料、页面、整库删除分别确认；不会删除项目源文件，不在后台恢复已删除资源。
7. 重建索引不调用模型；扫描失败保留可恢复信息，显示问题文件和诊断。
8. Memory 空关键词可浏览；来源会话失效、结构化内容和全局归属有明确呈现。
9. 系统任务与用户任务的 ID、状态和操作能力不会混用；未知进度不显示伪百分比。
10. 创建任务后原页可跟踪状态；任务终态清理保留审计与产物。
11. 运行时断开时保留已有内容并提示重连；局部失败不隐藏其它可用面板。
12. 在 1200×800、1440×900 和窄内容区检查文字、控件、长路径、键盘焦点；切主题后仍可读。

## 12. 建议实施顺序

1. 公共外壳、状态保留、默认浏览和已存在 RPC 的界面接入。
2. Wiki 领域对象、旧桶登记、项目关联、资料与人工页面工作区。这一阶段单独编写实现计划。
3. Memory 浏览维护、代码详情、任务能力与诊断补齐，按面板拆分后端与前端任务。

验收每个阶段后再进入下一阶段，避免同时重写所有存储和界面。本稿不授权执行迁移，也不要求提交现有工作区改动。
