# 输入区顶帽

- 日期：2026-09-25
- 状态：待审查
- 范围：GrenAgent 桌面端输入区（`electron-agent`）上方的排队、任务、目标
- 主题：这三层收成一条顶帽，底边塞进输入卡片。排队收起时带上第一条原文，展开后用手柄改顺序。

## 1. 背景

`MessageEditor` 里，`composer-dock` 把 `TodoDockFromStore`、`GoalPill`、`SteerQueue` 各画成一张独立卡片，叠在输入卡片上方，中间有缝。

排队的手柄现在只是 `GripVertical` 图标，不能拖。跟进顺序就是 `composerQueue` 数组顺序。回合空闲时，`ChatView` 发送数组第一项。

这次只改这三层的外壳和排队的收起、展开、排序。工作区条、附件、正文、底栏不动。

## 2. 目标 / 非目标

**目标**

1. 排队、任务、目标共用一条顶帽。从上到下是：排队、任务、目标。目标贴住输入卡片。
2. 顶帽底边塞进输入卡片，连成一块。三层不再各自使用 `dockCard` 的边框、圆角和底色。
3. 某一层没有内容就不占行。三层都没有时，顶帽不出现。
4. 排队默认收起。收起行是 `排队 · {条数} · {第一条原文}`。原文是 `composerQueue[0].text`，单行，放不下就截断。展开后标题仍是这一行，下面每条跟进各一行。
5. 展开后的每一行左侧有拖拽手柄。只有按住手柄移动才改顺序。引导、编辑、删除仍是原来的按钮，点它们不开始拖拽。
6. 排序只改本地 `composerQueue` 的先后。空闲时仍发送数组第一项。正在编辑的那条被拖走，编辑状态跟着它的 id。拖的那条已经不在队列里，松手不改顺序。
7. 任务保持现在的收起、展开和计数。目标始终一行，完成后仍然显示。暂停、编辑、清除、展开详情留在目标行。

**非目标**

- 不改工作区条、附件、正文、底栏、发送按钮。
- 不把目标完成后藏掉。
- 不把排队做成始终摊开的多条独立卡片。
- 不让任务或目标参与拖拽排序。
- 不新增拖拽库。手柄用指针事件重排数组。

## 3. 结构

在现在的 `composer-dock` 位置放一条顶帽外壳。外壳内部从上到下渲染：

1. 排队。没有 `composerQueue` 项时不渲染。
2. 任务。没有待办时不渲染，沿用 `TodoDock` 现在的空列表判断。
3. 目标。没有快照时不渲染，沿用 `GoalPill` 现在的判断。完成后仍渲染。

三层都空时，外壳不渲染，输入卡片外观与现在没有浮条时一致。

外壳只画顶边和两侧，上圆角与输入卡片的 `borderRadiusLG` 一致。底边不画。外壳 `margin-bottom: -1px`，压住输入卡片的顶边，两边框接上。顶帽里的文字不被输入卡片盖住。行与行之间用一条分隔线，不再套第二层卡片边框。

## 4. 排队

收起和展开跟任务条一样，点标题行切换。默认收起。

收起和展开时的标题都是：

`排队 · {n} · {composerQueue[0].text}`

`n` 是当前条数。第一条原文去掉首尾空白后单行显示，超出省略。悬停标题可以看到完整原文。第一条没有文字时，标题只显示 `排队 · {n}`。

展开后的每一行：

- 左侧手柄，可拖。
- 中间是这条跟进的原文。正在编辑时，中间换成现在的编辑框。
- 右侧保留引导、编辑、删除。

拖拽只比较排队内部的项。松手后按新顺序写回 `composerQueue`。`composerQueue.ts` 增加按 id 移动位置的纯函数，删除和改原文继续走现有函数。

编辑中的项被拖到新位置后，仍按 id 保持编辑，草稿不丢。拖拽开始后该项被删掉，则不写回顺序。

## 5. 任务和目标

任务仍由 `TodoDock` 提供收起摘要、进行中文案和展开列表。它失去自己的卡片外壳，列表行排在排队和目标之间。

目标仍由 `GoalPill` 提供状态句、条件、用时和操作。它始终是顶帽最后一行，不折叠。`status === 'complete'` 时继续显示。

## 6. 验收

- 三层都空时，没有顶帽。缺一层时，下面的层上移，不留空行。
- 有内容时，从上到下是排队、任务、目标。顶帽底边不画，用 1px 负边距压住输入卡片顶边，文字不被卡片盖住。三层都没有自己的卡片边框。
- 两条跟进时，收起行包含条数 `2` 和第一条原文。原文过长时单行截断。第一条没有文字时，标题只有条数。
- 展开后可拖动手柄交换两条顺序。交换后 `composerQueue` 的顺序改变，空闲时先发送新的第一项。
- 点引导、编辑、删除不改变顺序，点它们不进入拖拽。
- 编辑中拖动该条，编辑框仍在这一条上。该项消失后松手，顺序不变。
- 任务的收起、展开、计数与现在一致。有已完成目标时，目标行仍在最底。
- 工作区条、附件、正文、底栏的结构和操作不变。
