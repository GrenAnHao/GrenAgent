# 询问卡跨重启保持

- 日期：2026-09-24
- 状态：待审查
- 范围：GrenAgent 桌面端 `ask_user` 询问浮层
- 主题：未发送、未取消的询问卡在软件重启后仍在，已选内容一并恢复；发送或取消后才结束，并写回同一次工具调用。

## 1. 背景

`ask_user` 在有界面时阻塞在 `ctx.ui.input`。题目和已选内容只在内存里：`inlineQuestionStore` 保存当前请求，`InlineQuestionCard` 用组件状态保存选项、自定义文本、补充说明和图片。软件关闭后这些都没了。

重载会话时，`messagesFromAgent` 只在有 `toolResult` 时画出工具行。没有结果的 `ask_user` 不会出现「等待你选择」，浮层也不会再打开。

## 2. 目标 / 非目标

**目标**

1. 会话里最后一次没有工具结果的 `ask_user`，在重新打开该对话后弹出同一张浮层，会话流显示「等待你选择」。
2. 已选选项、自定义文本、补充说明和图片在未发送、未取消时一直保留，重启后填回。
3. 发送、点取消、或浮层开着时发送普通消息，才会结束这张卡。
4. 发送和取消把结果写回这次工具调用，模型从该结果继续，不另发一条用户消息。
5. 进程仍在、工具仍在等待时，发送和取消继续走现有 `extension_ui_response`。

**非目标**

- 不改浮层外观、`QuestionSelector`、审批卡。
- 不改无界面时对话流里的 `QuestionsCard`。
- 不恢复普通 `select` / `confirm` / `input` 浮层。
- 工具调用还没写入会话文件就崩溃时，不恢复卡片。
- 不把草稿放进模型上下文。

## 3. 架构

题目以会话里未完成的 `ask_user` 工具调用为准。草稿放在会话文件旁边，文件名为 `<sessionFile>.ask-user-draft.json`，按工具调用 id 对应，不进入模型上下文。

打开对话时，若会话中最后一次 `ask_user` 没有配对的工具结果，用该调用的参数重开浮层，并填回草稿。更早的未完成 `ask_user` 不再弹卡。

结束方式只有三种：

1. 发送：写入已回答的工具结果，删除草稿，模型从该结果继续。
2. 点取消：写入「用户取消了 ask_user 选择（未作答）。」，删除草稿，模型从该结果继续。
3. 浮层开着时发送普通消息：先按取消写回并删除草稿，再发送这条消息。

进程还活着且工具仍在等待时，前两种仍由 `extension_ui_response` 解除阻塞，工具自己写入结果。重启后没有等待中的调用，由宿主补写同一条 `toolCallId` 的工具结果，再继续模型，不插入用户消息。

## 4. 组件

- **未完成提问**：从会话消息找出最后一次没有工具结果的 `ask_user`，返回工具调用 id 和题目。没有则不恢复。
- **草稿文件**：读写已选选项、自定义文本、补充说明和图片。发送、取消或改发普通消息后删除。文件缺失、损坏，或其中的工具调用 id 与当前未完成调用不一致时，当作没有草稿。
- **重载会话**：`messagesFromAgent` 把这次未完成调用画成「等待你选择」。题目写入现有 `inlineQuestionStore`，浮层仍由 `ComposerPromptOverlay` 显示。
- **询问卡**：打开时填入草稿；每次改动立即写回草稿文件。活着的等待走 `extension_ui_response`；重启后的发送和取消走宿主补写。
- **普通消息**：浮层还在时先按取消结束这张卡，再发送。

## 5. 数据流

**进程还在、工具仍在等**

1. 用户改选项，草稿立即写入草稿文件。
2. 发送或取消走 `extension_ui_response`，`ask_user` 写入工具结果。
3. 模型从该结果继续。草稿删除。

**重启后打开同一对话**

1. 读会话，发现最后一次 `ask_user` 没有工具结果。
2. 用工具参数打开浮层，读草稿填回。没有可用草稿就是空白卡。
3. 发送或取消补写这次工具结果，再让模型继续。
4. 草稿删除。浮层和「等待你选择」消失。

**浮层开着时发送普通消息**

先按取消结束这张卡并删除草稿，再发送。进程还在时取消走现有回传，重启后走补写。

## 6. 错误处理

- 会话里没有未完成的 `ask_user`，或工具调用还没写入文件：不恢复，也不补写。
- 草稿缺失、损坏或 id 不符：打开空白卡，题目仍来自会话。
- 补写工具结果失败：浮层保持打开，草稿保留，并提示失败。不把答案改成一条新的用户消息。
- 同一次发送或取消只写一次结果。结果已经写入后再点，直接忽略。
- 存在更新的未完成 `ask_user` 时，只恢复最后一次。

## 7. 测试

- 会话末尾是没有工具结果的 `ask_user`：重载后浮层出现，会话里有「等待你选择」，题目与调用参数一致。
- 有匹配草稿：选项、自定义文本、补充说明和图片被填回。草稿损坏或 id 不符：空白卡，题目仍在。
- 已有工具结果，或后面又有更新的未完成 `ask_user`：只恢复最后一次，已回答的不再弹卡。
- 进程仍在等待：发送和取消仍走现有回传，成功后草稿删除。
- 重启后：发送写入已回答的工具结果并让模型继续；取消写入「用户取消了 ask_user 选择（未作答）。」；浮层开着时发普通消息先取消再发送。补写失败时浮层和草稿都还在。
- 重复发送或取消只产生一条工具结果。
