# Pi 0.84.2 Full Migration Design

## Goal

Complete the Pi `0.80.2` to `0.84.2` migration across the sidecar and extensions, then restore a clean workspace type check without changing intended agent behavior.

## Dependency Graph

The `cli` and `extensions` npm roots will both resolve Pi packages at `0.84.2`. Update only the `extensions` root manifest and lockfile; extension subpackages remain metadata-only manifests resolved through that root. Align root `typebox` to Pi's `1.3.7` dependency and add `@earendil-works/pi-agent-core` to the extensions root because `agent-mode` imports it directly.

This eliminates duplicate `ExtensionAPI` and `InlineExtension` types created by CLI Pi `0.84.2` versus extension Pi `0.80.2` installations.

## CLI Runtime Migration

Replace removed `AuthStorage` and `ModelRegistry.create()` use in `cli/src/main.ts` with Pi `0.84.2` `ModelRuntime`. Pass the created runtime to `createAgentSessionServices` and keep existing resource-loader configuration unchanged. Replace model probing's removed registry construction with `ModelRuntime.create()` and its model collection API.

## Extension Contract Migration

Pi `0.84.2` requires every tool result to contain `details`. Tools without structured details will return `details: undefined`, preserving their current content-only behavior. Replace removed `"success"` notification types with `"info"` while retaining existing messages and control flow. No deprecated TypeBox API is used, so no TypeBox source rewrite is required.

## Existing Type Diagnostics

Resolve the remaining diagnostics so full `cli` type checking is clean:

- Make the MCP call-tool abstraction accept the SDK's async-task result union rather than assuming every result has `content`.
- Convert the image-generation byte array to a `BlobPart` compatible representation.
- Correct long-term-memory argument types at the existing call sites.
- Correct self-evolve test tuple/undefined typing.
- Widen web-search tool details typing so all returned detail variants are valid.

These fixes are restricted to type correctness and must preserve current runtime behavior.

## Verification

From provisioned npm roots:

1. Pi resolves to `0.84.2` in both `cli` and `extensions`.
2. `npm run typecheck` from `cli` succeeds with zero diagnostics.
3. `npm test` from `cli` succeeds.
4. `npm run build` from `cli` succeeds.
5. Relevant extension tests for modified extension modules succeed where their package scripts provide them.

## Non-Goals

- Do not change extension package architecture or pin every subpackage's metadata declarations.
- Do not add a compatibility wrapper around Pi's removed APIs.
- Do not alter model-provider semantics, tool responses, or notification content beyond the Pi-required type-level migration.
- Do not modify unrelated uncommitted work outside this isolated worktree.

## Self-Review

- The dependency, runtime, extension-contract, and existing-diagnostic sections cover every categorized type-check failure.
- The design contains no placeholders or deferred migration steps.
- Scope remains a single coordinated dependency migration with directly related type repairs, rather than a broad extension refactor.
