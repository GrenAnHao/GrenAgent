# Pi 核心与供应商同步设计

## 目标

将 Pi 核心及扩展依赖升级到当前 npm 最新稳定版，并让系统供应商预设、模型同步与 Pi 运行时的内置模型目录保持一致。

## 范围

- 升级 `cli`、`extensions` 中 `@earendil-works/pi-*` 依赖及锁文件。
- 同步 Pi 内置供应商目录，保留供应商的协议与认证差异。
- 模型同步对内置模型、可枚举远程模型、不可枚举供应商分别处理。
- 不升级 `tauri-agent` 的 React、Vite、Tauri、Ant Design 等前端基础依赖。

## 方案

Pi `ModelRegistry` 作为内置模型的唯一来源。设置页通过 sidecar 暴露已解析模型；同步弹窗对内置供应商按 provider 过滤该结果，对自定义供应商继续调用远程模型接口。OAuth、图片供应商和动态网关不使用 API Key `/models` 假设，显示不可自动枚举状态并允许用户手动添加模型。

## 错误处理

模型列表为空或远程请求失败时保留现有错误状态，不修改已保存配置。供应商预设只补充元数据，不覆盖用户已保存的自定义模型和认证信息。

## 验证

运行 CLI typecheck/test/build、扩展测试及前端相关测试；记录完整 Tauri 构建所需的外部二进制缺失问题。
