# Pi 0.84.2 Full Migration Implementation Plan

> **For AI agents:** Required sub-skill: use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task by task. Use the checkbox syntax (`- [ ]`) to track progress.

**Goal:** Migrate the sidecar and extensions from Pi `0.80.2` to `0.84.2`, preserving behavior while making the full sidecar type check, tests, and build pass.

**Architecture:** Both npm roots resolve the same Pi package version so extension APIs have a single type identity. The CLI delegates runtime construction to Pi's `ModelRuntime` path, while extensions make Pi's now-required tool-result details explicit. The remaining diagnostics are localized type correctness repairs with existing behavior preserved.

**Tech Stack:** Node.js `>=22.19.0`, npm, Bun lockfile, TypeScript, Pi coding-agent `0.84.2`, Vitest, Node test runner, esbuild.

```ts

  AuthStorage,

with Pi `0.84.2`'s default runtime creation path:

  cwd,
  agentDir,
  resourceLoaderOptions,
});
```

Retain the existing `resourceLoaderOptions` object exactly. Pi creates the canonical `ModelRuntime` using `agentDir/auth.json` and `agentDir/models.json`.

- [ ] **Step 3: Construct the model probe from `ModelRuntime`**

Replace the dynamic legacy construction in `cli/src/probe-models.ts`:

```ts
const { AuthStorage, ModelRegistry } = await import("@earendil-works/pi-coding-agent");

```

with:

```ts
const { ModelRuntime, ModelRegistry } = await import("@earendil-works/pi-coding-agent");
const modelRuntime = await ModelRuntime.create({ allowModelNetwork: false });
const registry = new ModelRegistry(modelRuntime) as unknown as RegistryLike;
```

`allowModelNetwork: false` keeps the one-shot probe local while loading configured and cached model records.
