# Repo Wiki 项目文件

在 GrenAgent 左侧打开「Agent 数据」，选择「Repo Wiki」，会直接显示宿主已加载的项目。选择项目复用宿主的打开项目流程；Wiki 数据在当前项目内按需准备。进入页面不调用模型，也不逐个扫描或迁移其他项目。

生成任务由 AgentData 的 `agent_jobs` 持久化管理，阶段成果、源码快照、预算和写入租约保存在同一个 AgentData 数据库中。阅读页和「任务」标签显示同一任务的阶段、当前文档及可用操作。关闭页面、切换标签或项目不会取消生成；再次打开会接回任务。应用退出导致的暂停在下次启动时自动继续；用户手动暂停保持暂停，主动取消的任务不会自动重启。已确认的阶段成果可以在同一任务恢复时复用；源码、计划或模型身份变化会阻断原任务，重新分析或修复须再次确认。

Wiki 按准备、概览、计划、目录、生成、校验和发布推进；知识卡按准备、计划、生成、关系、校验和发布推进。目录冻结前进度不显示虚构的总数。成功条目可以预览为未发布草稿；部分条目失败时保留上次正式版本，修复以新任务关联原任务并复用身份一致的已确认成果。阅读页分别呈现已发布内容的新鲜度、任务运行状态、动作提交状态和当前准入状态，完成状态本身不代表源码已重新检查。

## 文件布局

默认语言为 `zh`。项目内保存以下事实文件：

```text
docs/repo-wiki/zh/
  project.json
  plan.json
  .execution-guard.json
  .transactions/
  namespaces/<namespace>/
    namespace.json
    pages/<页面>.md
    meta/<页面>.json
```

`project.json` 保存格式版本、项目身份和 revision 序列；`plan.json` 保存生成计划。namespace 区分分支、语言及 Wiki / 知识卡片空间。Markdown 是页面正文，旁边的 JSON 保存标题、来源、revision、生成基线与冲突候选。特殊页面 ID 使用可逆的安全文件名，原 ID 保留在元数据中；Wiki 支持 `modules/api` 这样的嵌套 ID，知识卡的正式页面 ID 使用 `cards/` 前缀，避免与同名 Wiki 页面冲突。namespace 的快照还记录已发布的源码 manifest 和条目输入，用于后续增量检查。

项目文件中的身份可以随仓库复制。应用内的运行身份按当前规范化目录、语言和文件身份派生，因此不同克隆目录分别使用自己的索引与写入上下文；删除索引后仍可得到相同运行身份。

这些文件可以随项目保存和版本管理。输出目录不会重新进入 Repo Wiki 的源码扫描。首次初始化兼容读取项目根的 `wiki_plan.json`；初始化后，项目内的 `plan.json` 是计划事实来源。

## 编辑和恢复

应用读取页面时会识别外部 Markdown 编辑。保存及冲突处理同时校验页面 revision 和文件 token；计划保存校验打开计划时的 token。发生并发修改时返回冲突，保留原文件，重新读取后再处理。

文件提交使用执行 fence 和可恢复 journal，将同一批必需成果作为一次发布。文件收据写入后，先重建索引再结算任务；中断时先核对收据和 journal，不重复生成已确认成果。恢复遇到未知内容会停止该项目的应用读写并保留备份，要求处理冲突；不会以 SQLite 中的旧副本覆盖文件。没有目录写权限、文件格式错误或迁移目标冲突时会明确报错。

未保存的界面草稿仍受离开保护；点击保存成功后才成为项目文件。源码检查和生成是显式操作，普通文档读取和运行状态查询不会全仓扫描。检查比较上次成功发布的文件哈希与实际工作区快照，Git 信息辅助说明；新增、修改、删除和搜索范围变化会使相关条目失效，结构变化重新规划。扫描覆盖不完整时不会把未知文件当成删除。分支与新鲜度使用上次检查结果，生成时重新检查源码。

## SQLite 与旧数据

`<应用数据目录>/repo-wiki/project-index.sqlite3` 是文件投影和索引。重建索引从项目文件恢复正文、人工修改、计划、历史 namespace 和 revision，不需要重新调用模型。进行中任务的已确认阶段成果由 AgentData 数据库保存，不依赖这个可重建索引。

旧 `workspace.sqlite3` 原件保留。仅打开当前项目时读取该项目及语言的旧页面、卡片和历史 namespace，迁移完成后以项目文件为准。重复迁移不会覆盖已有文件；目标存在不相容内容时返回冲突。迁移不会遍历其他宿主项目的源码。

GrenAgent 子进程在工作线程中制作旧库的一致性快照，复制期间仍可读取状态或取消；取消和退出会等待线程结束再清理暂存目录。项目文件已提交而索引更新失败时，会明确提示文件已保存，重新读取或重建索引即可恢复。损坏的事实文件会报错并保留原件；本轮不自动隔离或删除损坏的索引文件。

真实模型生成使用 GrenAgent 的系统知识模型与 WikiService 共享并发调度，源码外发前保留确认。Repo Wiki 工作进程通过 Pi SDK 的 Agent 运行受限的 `Read`、`Glob`、`Grep`、`ListDir` 会话；主进程的模型端口返回包含工具调用、停止原因与用量的完整助手消息。资料 Wiki 继续使用原有知识库和模型短调用路径。
