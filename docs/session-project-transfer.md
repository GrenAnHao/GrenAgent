# 会话移动到另一个项目

在错误的项目里开始或继续聊天后，可以把已保存的会话改到正确的本地项目，同时保留完整历史、草稿和文件出处。
移动改变的是**会话归属和运行环境**，不搬代码文件。

## 入口

在主会话行上右键（或悬停后的「更多」）选「移动到项目…」。两种会话行都能用：

- 项目下的会话行；
- 「对话」区里的对话行（只移动你点开的那一份会话，不批量搬同目录里的其他会话）。

已归档的会话和还没落盘的空白草稿没有这个入口。

## 选择目标

弹窗里可以：

- 选侧栏已有项目（列表里不出现会话当前所在项目，也不出现 `works` 下的临时对话目录）；
- 或用「选择本地目录」挑一个还没加进侧栏的本地文件夹。

弹窗始终显示会话当前项目的**完整路径**和目标的**完整路径**，并写明这一次不搬动、删除任何代码或生成文件。
目标目录必须已经存在且可访问；不会替你新建目录。选到与当前项目相同的目录（包括大小写、分隔符或目录链接
指向同一个真实目录）会提示「已经在这个项目里」，不写迁移记录、也不重建会话。

## 移动会保留什么

- 会话 ID、原条目 ID、会话文件路径都不变；标题和置顶也保留。
- 全部分支、标签、压缩摘要、上下文排除、工具关联和原消息正文都保留，旧消息不会被改写成目标项目的内容。
- 已结算的关联子代理及孙代理历史一起搬登记，主会话历史入口里仍能读到。
- 未发送的草稿（文字、图片、粘贴块、命令参数、文件标签）随会话保留，并且不会自动发送。
- 历史文件引用仍指向**原来的目录**：目标项目里即使有同名文件，点历史引用也不会打开它；文件被删了就如实报原路径不可用。

## 实际切换了什么

移动成功后：

- 侧栏只在目标项目下列出这份会话，源项目里的其他会话不受影响。
- 目标项目为你重新建立运行环境：项目规则、技能、配置、权限边界和文件管理上下文都取自目标项目。
- 工具初始工作目录是目标项目根，不会因为历史里切过目录而回到源项目。
- 模型、思考档位和 Fast 偏好保留；目标项目里不可用的模型只标出来，不会自动换成别的模型。

### 权限回退

执行模式和审批**只采用目标项目里明确配置过的本地策略**，并与源会话的请求取交集。目标项目没有对应授权时
回退为 Ask / 只读：Ask 不会自动升级成 Agent，源项目里用过的完全权限也不会被继承。需要更高权限时仍走
目标项目自己的确认流程。弹窗会说明授权与回退规则；打开后，输入栏显示当前生效的模式与审批。

## 什么时候不能移动

以下情况会被后端拒绝，并在弹窗里写出原因；移动本身不会替你取消任务：

- 会话正在执行回合，或还有排队中的消息；
- 关联的子代理还没结算，或还有后台命令没有退出；
- 会话正在等待批准或选择；
- Goal 仍在生效（即使暂时未武装，也请先暂停目标），或计划已确认／正在执行；
- 会话还在进行结构修改 / 等待恢复；
- 无法确认活动状态。

目标项目里别的运行中会话不会被停止、覆写或借用。

预览之后再产生新消息、确认位置或子代理集合发生变化，确认会提示「已过期，请重新预览」，不会用旧快照提交。

## 失败与恢复

- **提交前失败**：源会话完整保留，仍然可以正常打开；目标里不会出现可发送的半成品。
- **已经移动、但打开失败**：弹窗显示「已移动到目标项目，但打开失败」。这份会话已经归属目标项目，
  不会再移动一次；点「重新打开」只会补齐目标项目的登记和列表并重开，不重跑迁移。
  重复点确认、或提交回执丢失后重试，也返回同一个操作的结果。

## 打开的文件和终端

移动时留在右栏 / 终端里的东西不会被重新绑定到目标项目：

- 旧文件标签继续指向它们的真实原路径，未保存的编辑原样保留；目标项目的「文件管理器」是新开的标签，用目标项目根。
- 已经跑起来的终端仍在原来的目录；它不会被当成目标项目的终端，目标项目里的终端是另开的。
- 源项目其他会话的标签和任务不受影响。

## 用量与项目分组

移动不产生新的模型请求，也不增加历史 tokens 或费用。项目的用量报表按会话当前所属项目聚合，所以这次会话会
随归属换到目标项目分组；历史调用的来源、tokens、费用性质和去重身份都不变，未知来源仍为未知。之后在目标项目
发出的新请求只记一次、归到目标项目。

## 限制

- 一次只移动一个已落盘的主会话；不合并目标项目已有的会话，不做批量移动。
- 早期日志会在提交时升级为当前格式；原会话 ID 和已有条目 ID 保留，原本没有条目 ID 的旧日志会获得确定性 ID，消息正文不变。
- 不搬运源 / 目标项目的源码和生成文件，也不回传 Git 变更。
- 不恢复已撤回的会话树、导入 / 导出或归档列表里的移动入口。
- 运行中的任务不会热迁移：忙碌时请先等它结束。
- 移动过程中不要直接用旧版本应用继续写这份会话；有未完成事务时应让它恢复完成后再操作。
